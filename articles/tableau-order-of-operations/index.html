The order of operations: which filter runs first

Tableau applies filters, LODs and table calculations in a fixed sequence. Learn it as one diagram, then prove it on a top three stores view that gives the wrong answer until you add a context filter.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa DesktopLODTable calcsCertification

Short answer

Tableau does not apply your filters in the order you dragged them. It follows a fixed pipeline: extract filters, data source filters, context filters, then Top N and FIXED LODs, then ordinary dimension filters, then measure filters and only at the end table calculations. Most "Tableau is wrong" moments are a filter running earlier or later than the author assumed. The two everyday tools for moving work up the pipeline are Add to Context and the table calculation filter, which moves a filter to the very end.

The pipeline in one picture

Help pages and study guides draw steps 4 to 8 slightly differently. Tableau's own example says Top N and an ordinary dimension filter are applied independently, so the Top N ranks the data before the dimension filter can narrow it. Both readings give the same result on screen. Exactly where blending, totals and forecasts sit is drawn in the official diagram; read it there before an exam rather than trusting any copy, including this one.

What you will build

One Harbour Goods sheet that ranks stores, then four filters that land at different steps of the pipeline:

  • a Top 3 filter with a Category filter beside it, which gives a wrong answer;
  • the same with Category as a context filter, which fixes it;
  • a measure filter on SUM(Sales);
  • a table calculation filter that hides rows without changing percent of total.

Before you start

  • Tableau Desktop or Tableau Public.
  • The cleaned Harbour Goods orders, products and stores. The cleaned file has 55 orders: the 60-row sample less its five deliberate faults.
  • Connect with Connect > To a File > Text file, pick the orders file and drag the two others onto the canvas so they relate on the id columns.
  • Create Sales with Analysis > Create Calculated Field:
[Quantity] * [Unit Price] * (1 - [Discount])

Steps

1. Rank the stores

  1. Drag Store Id to Rows and Sales to Columns. Sort descending with the sort icon on the axis.
  2. Drag Store Id to Filters. In the dialog open the Top tab, choose By field, set Top 3 by Sales and Sum. Select OK.

Three bars: ST-003, ST-019 and ST-014.

2. Ask for the top three Kitchen stores

The manager wants the three best stores for Kitchen products. Drag Category to Filters and keep only Kitchen.

You still see ST-003, ST-019 and ST-014, now with their Kitchen sales. That answers a different question: "how much Kitchen did the top three stores overall sell?". Chennai (ST-007) sold more Kitchen than either Bengaluru or Pune but is missing. The Top N ranked all categories before the Category filter had a say.

3. Promote the filter to context

Right-click the Category pill on Filters and select Add to Context. It turns grey and moves above the Top N in the pipeline. The Top 3 now ranks Kitchen sales only and Chennai appears.

The same move fixes a FIXED LOD that ignores a dimension filter. See LOD expressions for that case.

4. Add a measure filter

Remove both filters. Drag Sales to Filters, choose Sum, then At least with a value of 20000. This is step 7 in the diagram. It runs on the aggregated value after dimension filters, so it keeps stores whose quarter total reaches 20,000.

5. Keep percent of total under a filter

  1. Remove the measure filter. Right-click SUM(Sales) on Columns and select Quick Table Calculation > Percent of Total.
  2. Drag Region to Filters and keep West. The two West stores now read as shares of West only. A dimension filter ran first and the table calc only saw two rows.
  3. Remove the Region filter. Create a calculated field called Region (table calc filter):
LOOKUP(MIN([Region]), 0)
  1. Drag it to Filters and keep West.

LOOKUP makes the field a table calculation, so the filter moves to step 9. The percent of total is computed on all six stores first, then four are hidden. The bars now show each West store's share of the whole company.

6. Know where the source filters sit

Two more filters run before everything on the sheet:

  • Data source filters, set on the Data Source page with Filters > Add or from Data > Edit Data Source Filters. They apply to every sheet and are respected by FIXED expressions.
  • Extract filters, set when you create the extract with Data > Extract Data. Rows filtered here are never in the extract at all.

Where this breaks

  • Context filters cost something. On a live connection Tableau may build a temporary table for the context. Use context for filters that cut the data a lot and rarely change, not for every quick filter on a dashboard.
  • The table calc filter only hides. All the rows are still queried. It is the right tool for keeping a percent of total intact, not for speed.
  • Filter actions are dimension filters. A dashboard filter action lands at step 5, so a FIXED number on the target sheet will not move. Readers notice.
  • Sets come before dimension filters. A Top N set behaves like the Top N filter in step 2. Combine it with a context filter for the same reason.
  • Totals sit late. Grand totals are computed after measure filters, so a filtered grand total is the total of what is left, not of everything.

On the brewhouse floor

A brewery wants its three best-selling beers in kegs. Rank beers with Top 3, filter Package to Keg and the view shows the top three overall beers' keg sales, which quietly drops a draught-only seasonal that outsells them on tap. Add Package to context and the seasonal appears. The same habit protects a quality report: a FIXED average gravity per beer ignores a tank filter until the filter goes into context.
