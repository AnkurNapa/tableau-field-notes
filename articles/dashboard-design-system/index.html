A dashboard design system your team will actually use

Audit how inconsistent your dashboards are, then ship a colour palette, type scale, layout grid and template workbook that make the next dashboard consistent by default.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 3 Ankur Napa DesktopDesign

Short answer

A design system for Tableau is four things a new author gets without asking: a colour palette installed in Tableau, a type scale set with Format > Workbook, a layout grid built into a template workbook and a one-page rulebook that says when to use each. Style guides in a PDF do not survive contact with a deadline. A template that opens already right does. Start by measuring how inconsistent things are, because "our dashboards look different" persuades nobody and "we use 31 colours and 9 font sizes" does.

The symptom

Harbour Goods has around twenty published dashboards. Each region built its own. Store managers moving from the South dashboard to the West one have to relearn where the filters are, what blue means and whether the total is at the top or the bottom. A reviewer spends half of each review on colours and alignment instead of numbers.

Measure it

A Tableau workbook (.twb, or the .twb inside a packaged .twbx) is XML. Every colour, font size and dashboard size is in it. Count them across the estate with a short script.

"""Count colours, font sizes and dashboard sizes across Tableau workbooks."""
import re
import sys
import zipfile
from collections import Counter
from pathlib import Path

def workbook_xml(path):
    if path.suffix == ".twbx":
        with zipfile.ZipFile(path) as z:
            name = next(n for n in z.namelist() if n.endswith(".twb"))
            return z.read(name).decode("utf-8", "replace")
    return path.read_text(encoding="utf-8", errors="replace")

colours, fonts, sizes = Counter(), Counter(), Counter()
for p in Path(sys.argv[1]).rglob("*.twb*"):
    xml = workbook_xml(p)
    colours.update(c.lower() for c in re.findall(r"#[0-9a-fA-F]{6}\b", xml))
    fonts.update(re.findall(r"attr='font-size' value='(\d+)'", xml))
    sizes.update(re.findall(r"<size [^>]*maxwidth='(\d+)'", xml))

print("distinct colours:", len(colours))
print("font sizes:", sorted(fonts, key=int))
print("dashboard widths:", sizes.most_common())

Run it with python3 audit_workbooks.py <folder>. Use the TSC library or the REST API to download the published workbooks first if they only live on the server. The XML attribute names are stable in practice but not a documented contract, so treat the counts as an estimate and spot-check a workbook by hand.

Write down four numbers: distinct colours, distinct font sizes, distinct dashboard sizes and how many dashboards use automatic size. That is your baseline.

Fix it

1. A palette with tested contrast

Pick colours for meaning first, then check them. Every categorical colour below passes the 3 to 1 non-text contrast in WCAG 2.2 against white. The text colours pass 4.5 to 1.

TokenHexRatio on whiteUse
Primary#1F4E798.66The measure that matters, actual
Accent#B35C004.72Highlight, selected, the one thing to look at
Category 3#0F6E6E6.04Third series
Category 4#6A3D9A7.64Fourth series
Category 5#8C564B5.92Fifth series
Neutral#5A5A5A6.90Everything else, comparison, prior period
Text#33333312.63Titles, labels
Text secondary#7676764.54Axis labels, captions

Five categorical colours is a deliberate ceiling. A sixth series is a sign to group, filter or use small multiples. For a sequential palette from #D9E2EC to #1F4E79, the light end is only 1.31 to 1 on white, so label low values or add a mark border.

Install it. In Tableau Desktop 2025.3 and later, create the palette in the Edit Colors dialog with Create Custom Palette at the end of the palette list. In 2025.2 and earlier, add it to Preferences.tps in My Tableau Repository and restart Tableau Desktop:

<?xml version='1.0'?>
<workbook>
  <preferences>
    <color-palette name="Harbour Goods categorical" type="regular">
      <color>#1F4E79</color>
      <color>#B35C00</color>
      <color>#0F6E6E</color>
      <color>#6A3D9A</color>
      <color>#8C564B</color>
    </color-palette>
    <color-palette name="Harbour Goods sequential" type="ordered-sequential">
      <color>#D9E2EC</color>
      <color>#1F4E79</color>
    </color-palette>
  </preferences>
</workbook>

The type values are regular, ordered-sequential and ordered-diverging. Ship the file to every author's machine with whatever tool your IT team uses for software settings. A palette on one laptop is a preference, not a system.

2. A type scale

Set it once per workbook in Format > Workbook. Pick one font family your audience's machines and the server have; a font missing on the server falls back silently. Four sizes are enough:

RoleSizeWeight
Dashboard title18 ptBold
Worksheet title12 ptBold
Body, labels, tooltips10 ptRegular
Captions, axis9 ptRegular, #767676

Workbook-level font changes overwrite font changes made at worksheet level. That is the behaviour you want for a system and the one that surprises people editing an old workbook.

3. A layout grid in a template

Build one template workbook and make it the only way to start:

  • Fixed size, 1200 by 800 pixels, for desktop viewing. Fixed size also lets the server cache views.
  • An 8 pixel grid: turn on Dashboard > Show Grid and set the size in the grid options (the label may read Grid Options).
  • A header container 64 pixels high with the title on the left and the data freshness date on the right.
  • A filter row under the header, always in the same order: date, region, store.
  • A KPI row of three to five numbers, then the main chart, then the supporting views.
  • Padding of 16 pixels outside containers and 8 inside. Rhythm comes from these two numbers.
  • A text object at the bottom with the data source, the definition of each KPI and a contact.

Add objects in reading order, because screen readers follow the order objects were added. See accessible dashboards.

Publish the template to a project called Templates on Tableau Server or Cloud so authors download it. Keep the master copy under version control.

4. A rulebook on one page

Ten rules authors can remember. Primary colour for actual, neutral for comparison, accent for one thing only. Titles state the finding. Every KPI links to its definition. No dashboard without the footer. Review against this page, not against taste.

Prove it

Run the audit script again after a quarter. The numbers below are illustrative of what a team of this size usually sees; replace them with your own.

MeasureBeforeAfter one quarter
Distinct colours across workbooks319
Distinct font sizes94
Dashboards with automatic size12 of 202 of 20
Review comments on formatting, per review61

Where this breaks

  • Old workbooks. The system applies to new work. Pick the five most-used dashboards and migrate those; leave the long tail.
  • The palette that is too clever. Eight subtle blues look calm and read badly. Test every palette for contrast and with a colour vision deficiency simulator before shipping it.
  • Fonts on the server. A font installed on authors' laptops but not on Tableau Server renders as a fallback. Check a published view, not Desktop.
  • Templates fork. Someone copies the template, changes the header and that copy spreads. Version the template and say which version a dashboard uses in its footer.
  • Mobile. A 1200 by 800 layout does not shrink well. Add a phone layout from Device Preview for dashboards people read on the shop floor.

Next

Consistent dashboards still fail if two of them show different numbers for the same KPI: One KPI, one definition.

On the brewhouse floor

A brewery's dashboards should agree on what each colour means across production, quality and sales. If the primary colour is actual hectolitres on the production dashboard, it is actual hectolitres on the sales one too. Amber always means "check this tank". The template's footer carries the definition of brewhouse yield, so nobody wonders whether it was measured at the kettle or in the fermenter. The executive KPI scorecard build uses the same fixed grid and KPI row.
