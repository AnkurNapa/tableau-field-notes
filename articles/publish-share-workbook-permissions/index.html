Publish and share without oversharing

Publish a small workbook to Tableau Cloud or Server, put it in a project that only one group can open and share the link. The goal is the least access that still works.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 1 Ankur Napa ServerCloudSecurityCertification

Short answer

Publishing is two decisions, not one. The first is where the workbook lives: a project. The second is who can do what there: permissions, set on the project and inherited by everything in it. Get the project right and you rarely touch permissions on a single workbook again. Sharing a link is the last step and the least important one, because a link does not grant access. Permissions do.

This works the same on Tableau Server and Tableau Cloud. The screens differ in small ways, which I point out as they come.

What you will build

One workbook, Harbour Store Sales, with one view: net sales by store. It goes into a new project, Harbour Sales, that only a group called Store Managers can open. Everyone else on the site sees nothing. You then share the view's link with a store manager and prove two things: she can see it and a colleague outside the group cannot.

The data is the Harbour Goods orders file: harbour-goods-orders.csv. It holds 60 rows from July to September 2026. It is the messy-data lesson file, so it has a duplicate order, a blank quantity, a negative quantity, an impossible date and one row for the unknown store ST-099. Leave them in. They make the check at the end honest.

Before you start

  • Desktop. Tableau Desktop, any recent version. The free Public Edition cannot publish to Server or Cloud.
  • Site role. Creator or Site Administrator Creator on the site, so you can connect to a file and publish it.
  • Site admin help. Creating the group needs a site admin. If that is not you, ask for a Store Managers group with one test user in it.
  • Two test users. One in Store Managers with the Viewer role. One outside it, any role. Use addresses you control.

Steps

1. Build the view

  1. In Desktop select File > Open (or Connect > To a File > Text file) and pick the CSV.
  2. Tableau may tidy the headers, so unit_price can appear as Unit Price. Use whichever names your Data pane shows.
  3. Select Analysis > Create Calculated Field. Name it Net Sales:
[Quantity] * [Unit Price] * (1 - [Discount])
  1. Drag Store Id to Rows. It is a discrete (blue) dimension.
  2. Drag Net Sales to Columns. It becomes SUM(Net Sales), continuous (green).
  3. Sort descending with the sort button on the toolbar. Rename the sheet Net sales by store.
  4. Save the workbook as Harbour Store Sales.

2. Create the project

On the site, select Explore, then New > Project. Name it Harbour Sales and select Create. On Server the button sits in the same place.

3. Set the project permissions

  1. On the new project, open ... > Permissions.
  2. You will see a rule for All Users. New projects copy the default project's rules. Those usually give All Users some access. Set the All Users rule template to None. None clears every capability to unspecified, which Tableau treats as denied.
  3. Select + Add Group/User Rule, pick Store Managers and set the project template to View and the workbook template to View.
  4. Leave Asset permissions as it is for now. Locking projects is a Level 3 topic.
  5. Select Save.

4. Publish

  1. In Desktop select Server > Sign In and enter your Server address or Tableau Cloud site.
  2. Select Server > Publish Workbook. If the menu item is missing, select a worksheet tab first, not the Data Source tab.
  3. Pick the Harbour Sales project and keep the name Harbour Store Sales.
  4. Under Permissions, keep the project's settings.
  5. Under Data Sources, select Edit. Choose to embed the data in the workbook. Because the source is a local file, Tableau packages a copy of it.
  6. Leave Show Sheets as Tabs cleared. One view is the point.
  7. Select Publish. The workbook opens in the browser when it is done.

5. Share the link

  1. Open the view. On the toolbar select Share.
  2. Select Copy Link and send it to your Store Managers test user. You can also type her name in the share box, which sends her a notification.

Sharing does not change permissions. It only tells someone where to look.

Check it worked

First, check the numbers match Desktop. The published view should show seven stores and these totals, rounded to the paisa:

ST-0141332,714.75
ST-0191132,640.90
ST-007419,070.45
ST-011918,930.35
ST-022712,285.35

Add the count field Tableau names after the file to see the row counts. ST-011 has nine rows but one has a blank quantity, so SUM skips it. ST-003 includes a return of minus two towels, which takes 1,098 off its total. ST-014 counts the duplicate order twice. If your totals differ, you probably filtered out nulls or fixed the data before publishing. Both are fine for a real workbook and wrong for this check.

Then check the access:

  1. Sign in as the Store Managers test user. The link opens the view. There is no Edit button, because she is a Viewer.
  2. Sign in as the other test user and open the same link. Tableau should refuse it. The project does not appear under Explore either.
  3. As the site admin, open the workbook's ... > Permissions and select the test user's name in the effective permissions view. It should show View allowed and nothing else.

If the outsider can see the view, the All Users rule still grants something. Check the project and the workbook.

Where this breaks

  • The file goes stale. A packaged local file is a snapshot. Tableau Cloud cannot reach a CSV on your laptop to refresh it. Publish a data source from a database, or use Tableau Bridge for files on your network. That is the next Level 2 step.
  • Prompt user. If you publish a database connection with Prompt user instead of embedded credentials, every viewer needs their own database login. Extract refresh schedules need Embed password or Allow refresh access.
  • The owner can always see it. You own the workbook, so you have every capability on it. Test as someone else, never as yourself.
  • A user rule beats a group rule. If someone added a user-level Allow for the outsider, it wins over a group Deny. User rules are evaluated before group rules.
  • Copies and downloads. A Creator in Store Managers with the Explore template could save a copy elsewhere. Keep the template at View until you mean otherwise.
  • The site role caps everything. Granting Web Edit to a Viewer does nothing. The role never allows it.

On the certification

Next on the roadmap

You embedded the data inside the workbook. Next, publish one certified data source that many workbooks share and give it a refresh schedule: One certified data source, many workbooks. If you need each manager to see only her own stores, that is Row-level security that holds.

On the brewhouse floor

A brewery shares a fermentation dashboard the same way. Put it in a Brewhouse project that only the brewing group can open, publish it there and send the link to the shift brewers. The sales team does not need tank temperatures. The project keeps them out without anyone having to remember. The link is the easy part. The project is what stops the taproom manager finding a half-built yield calculation and quoting it at a meeting. For the dashboard itself, see a live fermentation-monitoring dashboard.
