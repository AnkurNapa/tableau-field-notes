Sandbox and your first REST call: sign in and list workbooks

Get a Tableau Cloud developer sandbox, create a personal access token, sign in to the REST API with curl and list the workbooks on the site. Then do the same in five lines of Python.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 1 Ankur Napa APICloudSecurity

Short answer

Sign in once, keep the token, send it with every call. You POST your personal access token (PAT) name and secret to /api/3.29/auth/signin. Tableau Cloud sends back a credentials token, the site ID and your user ID. Every later call carries the credentials token in the X-Tableau-Auth header and uses the site ID in its URL. Listing workbooks is GET /api/3.29/sites/<site-id>/workbooks. When you finish, POST to /auth/signout so the token dies.

What you will build

A sandbox site with one published workbook, one PAT called rest-first-call and three shell commands: sign in, list workbooks, sign out. Then the same calls through Tableau Server Client in Python, so you can see what the library hides.

The workbook is anything built on the Harbour Goods orders file: harbour-goods-orders-clean.csv. It holds 55 orders from six stores between 2 July and 29 September 2026. Its contents do not matter for this step; the API only needs something to list.

Before you start

  • A developer sandbox. Request one from the Tableau Cloud developer sandbox page. The form asks for a business email. Activation instructions arrive by email. If you already have a Tableau Cloud site you are allowed to test on, use that instead.
  • Your pod and site name. Sign in and read the browser address bar. In https://10ay.online.tableau.com/#/site/harbourdev/home the pod is 10ay and the site name, which the API calls contentUrl, is harbourdev. Yours will differ. Below they appear as <pod> and <site-content-url>.
  • PATs switched on. Sites activated since Tableau 2023.2 start with PAT creation off. If you are the sandbox admin, go to Settings > Personal Access Tokens and allow it.
  • curl and jq. Both ship with macOS and most Linux distributions, or install from the package manager. On Windows use PowerShell 7 with Invoke-RestMethod, or Git Bash.
  • Python 3.10 or later for the last part.

Steps

1. Publish one workbook

  1. In Tableau Cloud select Explore > the Default project.
  2. Select New > Workbook. In Connect to Data choose Files and upload the CSV.
  3. Drag store_id to Rows and quantity to Columns. Save the workbook as Harbour Goods Orders.

Publishing from Tableau Desktop with Server > Publish Workbook works as well.

2. Create the personal access token

  1. Select your profile image > My Account Settings.
  2. Scroll to Personal Access Tokens. Type rest-first-call as the token name and create it. The button label may read Create Token or Create new token.
  3. Copy the secret straight into your password manager. Tableau shows it once.

3. Put the secrets in environment variables

Never paste a token into a command you might share or a file you might commit.

export TABLEAU_SERVER="https://<pod>.online.tableau.com"
export TABLEAU_SITE="<site-content-url>"
export TABLEAU_PAT_NAME="rest-first-call"
read -rs TABLEAU_PAT_SECRET && export TABLEAU_PAT_SECRET
export API="$TABLEAU_SERVER/api/3.29"

read -rs waits for you to paste the secret and keeps it out of your shell history.

4. Sign in

curl -s -X POST "$API/auth/signin" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d "{\"credentials\": {
        \"personalAccessTokenName\": \"$TABLEAU_PAT_NAME\",
        \"personalAccessTokenSecret\": \"$TABLEAU_PAT_SECRET\",
        \"site\": {\"contentUrl\": \"$TABLEAU_SITE\"}}}" \
  > signin.json

export TOKEN=$(jq -r '.credentials.token' signin.json)
export SITE_ID=$(jq -r '.credentials.site.id' signin.json)
jq '.credentials | {site: .site.contentUrl, site_id: .site.id, user_id: .user.id}' signin.json

Without Accept: application/json the REST API answers in XML. Both formats carry the same fields.

5. List the workbooks

curl -s "$API/sites/$SITE_ID/workbooks?pageSize=100" \
  -H "X-Tableau-Auth: $TOKEN" \
  -H "Accept: application/json" \
  | jq '{total: .pagination.totalAvailable,
         workbooks: [.workbooks.workbook[]? | {name, project: .project.name, updatedAt}]}'

The ? after workbook[] stops jq failing when the site is empty.

Filtering happens on the server. To see only one project, add a filter expression:

curl -s "$API/sites/$SITE_ID/workbooks?filter=projectName:eq:Default" \
  -H "X-Tableau-Auth: $TOKEN" -H "Accept: application/json" | jq '.pagination'

6. Sign out

curl -s -X POST "$API/auth/signout" -H "X-Tableau-Auth: $TOKEN" -o /dev/null -w "%{http_code}\n"
rm signin.json

7. The same thing in Python

python3 -m venv .venv && source .venv/bin/activate
pip install tableauserverclient
import os

import tableauserverclient as TSC

auth = TSC.PersonalAccessTokenAuth(
    os.environ["TABLEAU_PAT_NAME"],
    os.environ["TABLEAU_PAT_SECRET"],
    site_id=os.environ["TABLEAU_SITE"],
)
server = TSC.Server(os.environ["TABLEAU_SERVER"], use_server_version=True)

with server.auth.sign_in(auth):
    print("REST API version in use:", server.version)
    for wb in TSC.Pager(server.workbooks):
        print(f"{wb.project_name:<20} {wb.name}")

In TSC the site_id argument takes the site's content URL, not its LUID. The name is historical. The with block signs out for you, even when the code inside fails.

Check it worked

  • The sign-in output shows site equal to your <site-content-url> and two IDs in the xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx shape.
  • The workbook list shows total as "1" on a fresh sandbox, with Harbour Goods Orders in the Default project. The count arrives as a string in JSON, which catches out anyone comparing it to a number.
  • If your sandbox came with sample content, total equals the number of workbooks you see under Explore with All Workbooks selected.
  • The sign-out call prints 204.
  • The Python script prints REST API version in use: 3.29 or a later version and the same workbook names.

Where this breaks

  • 401 on sign-in. The usual causes are a wrong contentUrl (it is case sensitive), a pod that does not match the site or a revoked PAT. Expired PATs vanish from My Account Settings.
  • The second script logs the first one out. A PAT cannot hold two Tableau Cloud sessions at once. Two scheduled jobs sharing one token will fight. Give each job its own token.
  • The token expires mid-run. The credentials token lasts 240 minutes by default. Long jobs should catch a 401 and sign in again.
  • PATs quietly die. Tableau Cloud removes a PAT after 15 days without use. A monthly job needs a connected app or a token that something touches more often.
  • Only 100 rows came back. Every list call is paged. Read pagination.totalAvailable and request pageNumber=2, or let TSC.Pager walk the pages for you.
  • You see fewer workbooks than an admin. The API returns what your permissions allow. A PAT acts with exactly your site role.
  • Old version number. 3.29 was the newest version as of October 2026. If the docs list a newer one, change API. Older versions keep working, so this is about new features, not breakage.

On the brewhouse floor

The same three calls are the start of every brewery automation I have seen. A packaging manager wants to know which of forty dashboards still reads last year's keg-line data source. Sign in, list workbooks with their data sources, sign out. That takes thirty seconds instead of an afternoon of opening projects one by one. The answer is usually that six dashboards point at a spreadsheet someone saved to a shared drive in 2022.
