Dashboard extensions: build one, measure it and run it safely

Build a small dashboard extension with the Extensions API 1.17, measure how much data it reads and how long it takes, then cut its permissions to summary data and get it onto a Tableau Cloud safe list.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 3 Ankur Napa APIDesktopCloudSecurityPerformance

Short answer

A dashboard extension is a web page that runs inside a dashboard zone and talks to the workbook through tableau.extensions. A .trex manifest tells Tableau where the page lives and what it wants. Most extensions in the wild ask for more than they need: full data permission, an unvetted host and a read of every row on every filter change. The fix is to read summary data with getSummaryDataReaderAsync(), release the reader, drop full data from the manifest, host over HTTPS and let a site admin add exactly that URL to the safe list.

The symptom

A team asks for a "total units" badge on a dashboard that also shows the number as filters change. Someone finds an extension that does it by reading every underlying order row and adding them up. On Tableau Cloud it shows a prompt that says the extension wants full data access, the dashboard is slower and the admin will not safe-list it because nobody knows what it sends where.

You will build the honest version and keep the copied manifest for a moment to see the difference: units-badge, about 60 lines of JavaScript, reading the Units by store sheet of the Harbour Goods workbook built on harbour-goods-orders-clean.csv. Then you measure it.

Measure it

1. Build the files

Create a folder units-badge with four files. First the library, copied from the official repository:

mkdir units-badge && cd units-badge
curl -sO https://raw.githubusercontent.com/tableau/extensions-api/main/lib/tableau.extensions.1.latest.min.js

The manifest, units-badge.trex. The first version asks for full data, the way the copied extension did:

<?xml version="1.0" encoding="utf-8"?>
<manifest manifest-version="0.1" xmlns="http://www.tableau.com/xml/extension_manifest">
  <dashboard-extension id="com.example.harbour.unitsbadge" extension-version="0.1.0">
    <default-locale>en_GB</default-locale>
    <name resource-id="name"/>
    <description>Shows total units for the Units by store sheet</description>
    <author name="Harbour Goods analytics" email="analytics@example.com"
            organization="Harbour Goods" website="https://www.example.com"/>
    <min-api-version>1.10</min-api-version>
    <source-location>
      <url>http://localhost:8765/index.html</url>
    </source-location>
    <icon>PASTE_BASE64_70x70_PNG_HERE</icon>
    <permissions>
      <permission>full data</permission>
    </permissions>
  </dashboard-extension>
  <resources>
    <resource id="name">
      <text locale="en_GB">Units badge</text>
    </resource>
  </resources>
</manifest>

The icon must be a 70 by 70 pixel PNG, Base64 encoded. On macOS base64 -i icon.png | tr -d '\n' prints it.

The page, index.html:

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Units badge</title>
  <script src="tableau.extensions.1.latest.min.js"></script>
  <script src="badge.js" defer></script>
  <style>
    body { font-family: system-ui, sans-serif; margin: 8px; }
    #total { font-size: 2.5rem; font-weight: 700; }
    #meta { font-size: 0.8rem; color: #555; }
  </style>
</head>
<body>
  <div id="total" aria-live="polite">...</div>
  <div id="meta"></div>
</body>
</html>

The logic, badge.js. It times every read and counts the rows it touches:

'use strict';

const WORKSHEET = 'Units by store';
const MEASURE = 'SUM(quantity)';

async function readTotal (worksheet) {
  const started = performance.now();
  const reader = await worksheet.getSummaryDataReaderAsync(undefined, { ignoreSelection: true });
  let total = 0;
  let rows = 0;
  try {
    for (let page = 0; page < reader.pageCount; page++) {
      const table = await reader.getPageAsync(page);
      const col = table.columns.find((c) => c.fieldName === MEASURE);
      if (!col) throw new Error(`No ${MEASURE} on ${worksheet.name}`);
      for (const row of table.data) {
        total += Number(row[col.index].value) || 0;
        rows += 1;
      }
    }
  } finally {
    await reader.releaseAsync();
  }
  const ms = Math.round(performance.now() - started);
  return { total, rows, ms };
}

async function render (worksheet) {
  const out = document.getElementById('total');
  const meta = document.getElementById('meta');
  try {
    const { total, rows, ms } = await readTotal(worksheet);
    out.textContent = total.toLocaleString('en-IN');
    meta.textContent = `${rows} marks read in ${ms} ms`;
  } catch (err) {
    out.textContent = '?';
    meta.textContent = err.message;
  }
}

tableau.extensions.initializeAsync().then(() => {
  const dashboard = tableau.extensions.dashboardContent.dashboard;
  const worksheet = dashboard.worksheets.find((w) => w.name === WORKSHEET);
  if (!worksheet) {
    document.getElementById('meta').textContent = `Add a sheet called ${WORKSHEET}`;
    return;
  }
  render(worksheet);
  worksheet.addEventListener(tableau.TableauEventType.FilterChanged, () => render(worksheet));
}, (err) => {
  document.getElementById('meta').textContent = `Initialise failed: ${err.message}`;
});

2. Serve it and add it to a dashboard

python3 -m http.server 8765

In Tableau Desktop open the workbook, rename the bar chart sheet to Units by store and put it on a dashboard with a store_id filter. From Objects drag Extension onto the dashboard. In Add an Extension select Access Local Extensions and open units-badge.trex. Tableau shows the full data prompt; allow it for now.

3. Attach a debugger

Close Desktop and start it with remote debugging switched on. On macOS, with your own version number in the path:

open "/Applications/Tableau Desktop 2026.2.app" --args --webEngineArgs --remote-debugging-port=8696

On Windows:

"C:\Program Files\Tableau\Tableau 2026.2\bin\tableau.exe" --webEngineArgs --remote-debugging-port=8696

Open http://localhost:8696 in Chrome and pick the extension page. Tableau 2025.2 and later embed Chromium 108, so use Chrome 108 or later. The Network tab shows every request the extension makes. The Console shows errors.

4. Record three numbers

Read them from the badge's own meta line and from DevTools:

MeasureWhereWhat to note
Rows read per rendermeta lineMarks, not database rows
Time per rendermeta lineMilliseconds from reader open to release
Outbound hostsDevTools > NetworkEvery domain other than localhost

Then change the store filter five times and watch whether the time grows. A reader that is never released holds memory in Tableau, so a leak shows as renders getting slower.

Fix it

  1. Read summary data, not full data. The badge only needs the six aggregated marks. getSummaryDataReaderAsync() is the current method from Tableau 2022.4 and API 1.10; getSummaryDataAsync() is deprecated. Full data methods (getUnderlyingTableDataReaderAsync) read rows from the logical tables and need the viewer to hold Download Full Data permission.
  2. Remove the permission. Delete the whole <permissions> block from the manifest. An extension that does not declare full data cannot call the full data methods; they fail. That is the point.
  3. Always release the reader. The finally block calls releaseAsync() even when a page read throws.
  4. Stop fetching from the internet. Load the library from your own host, as above, not from a CDN you do not control. No analytics scripts, no fonts from third parties. The admin can then read the Network tab and see one host.
  5. Host over HTTPS. Tableau allows plain HTTP only for localhost. Change source-location to your HTTPS URL, bump extension-version to 0.2.0 and keep the id the same.
  6. Ask for the safe list. On Tableau Cloud a site admin goes to Settings > Extensions, keeps Allow extensions to run on this site on and adds your exact URL under Enable Specific Extensions. They set Full Data Access to Deny and can hide the user prompt. Sandboxed extensions hosted by Tableau run by default; network-enabled ones like this run only from the safe list.

Prove it

The figures below are illustrative. I have not timed this build on a live site, so measure your own.

MeasureBefore (full data)After (summary only)
Rows read per render55 order rows (underlying data)6 marks
Prompt on Tableau CloudAsks for full data accessNo full data line
Outbound hostsExtension host plus a CDNExtension host only
Badge value, no filter103103
Badge value, ST-003 only2929

The value check matters most. The total of SUM(quantity) across all six stores is 103 and ST-003 alone is 29, computed from the CSV. If the badge disagrees with the bar chart, the extension is reading the wrong sheet or the wrong column.

Where this breaks

  • Field names are what the sheet shows. SUM(quantity) becomes AGG(...) or a renamed caption if someone edits the sheet. Match on a field the author agrees not to rename. Show an error rather than a zero.
  • Selection. ignoreSelection: true reads all marks. Without it, a user's selection changes the total, which surprises people.
  • Summary data still leaks. Summary data is aggregated, not harmless. Six store totals can be commercially sensitive. Treat every extension URL as a data destination.
  • Version drift. A manifest that says min-api-version 1.10 will not load in Tableau older than 2022.4. Check the oldest Desktop your users run.
  • Cloud debugging is different. Desktop's debug port does not apply to a viz in a browser on Tableau Cloud. Use the browser's own DevTools there.
  • Leaving the debug port open. The docs warn that leaving QTWEBENGINE_REMOTE_DEBUGGING set gives unauthenticated access to the extension runtime. Close Desktop after debugging and unset it if you used it.

On the brewhouse floor

A distillery's blending team wants a badge on the cask dashboard that reads "litres of pure alcohol in the selection" as they filter by warehouse and fill year. Summary data is enough: the sheet already sums the LPA per warehouse. Full data would hand the extension every cask record, fill strength and owner. Build it the summary way and the excise team signs it off in a day instead of a month. My maturing-stock valuation dashboard is the kind of sheet it would sit on.
