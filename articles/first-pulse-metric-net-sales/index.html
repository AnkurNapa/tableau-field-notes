Your first Pulse metric: net sales that reports itself

Publish a small orders data source to Tableau Cloud, define a Net Sales metric in Tableau Pulse, follow it and read the digest. Then check Pulse's numbers against the file before anyone trusts them.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 1 Ankur Napa PulseAICloud

Short answer

A Pulse metric starts life as a metric definition: one measure, one aggregation, one time dimension and the filters people may change. You build it on a published data source in Tableau Cloud, save it and Pulse creates the first metric. People follow metrics, not definitions. Pulse sends them a digest by email or Slack. Pulse is Tableau Cloud only in October 2026. Expect about twenty minutes, most of it spent publishing the data source.

What you will build

One published data source called Harbour Goods Orders, one metric definition called Net Sales and one followed metric with a weekly digest.

The data is two quarters of orders for Harbour Goods, the fictional retailer used across this site. It holds 105 orders from 1 April to 29 September 2026. Every row already carries its store, city, region, product category and net sales in rupees, so there is no join and no calculation to write. The July to September rows are the cleaned orders from the shared sample; April to June are synthetic rows generated with a fixed seed. Download it: first-pulse-metric-net-sales.csv.

Why a flat file? Pulse reads one published data source. If the definition depends on a relationship you have not tested, the first wrong number will be blamed on Pulse.

Before you start

  • Site. A Tableau Cloud site. A trial works. Pulse does not run on Tableau Server.
  • Pulse switched on. Pulse is off by default. A site administrator turns it on under Settings > Tableau Pulse > Deployment > Turn on Tableau Pulse, for everyone or for one group, then selects Save.
  • AI summaries (optional). The written summary in the digest is a separate switch: Settings > General > AI in Tableau > Tableau Pulse: Summarizes key metric insights. It is off by default.
  • Site role. Creator, Site Administrator Explorer or Explorer (can publish) to create a definition. Viewers can follow metrics but cannot define them.
  • Tableau Desktop to publish the data source. You can also upload the file through web authoring if your site allows it.

Steps

1. Publish the data source

  1. In Tableau Desktop select File > New, then under Connect > To a File select Text file and open the CSV.
  2. On the Data Source page check the types. order_date must be a date, net_sales a number (decimal). Fix either with the type icon above the column if Desktop guessed wrong.
  3. Under Connection select Extract. A file connection published as live cannot be refreshed from Tableau Cloud. An extract is the easier object for Pulse.
  4. Go to a worksheet, then select Server > Publish Data Source > Orders (the name follows your connection). Sign in to your Cloud site if asked.
  5. Choose a project, name it Harbour Goods Orders and select Publish. Save the extract file where Desktop prompts you.

2. Create the metric definition

  1. In Tableau Cloud open Tableau Pulse and select New Metric Definition.
  2. Choose Harbour Goods Orders and select Connect.
  3. Name: Net Sales. Description: "Quantity times unit price less discount, in rupees. Excludes duplicate, unknown store and bad date rows."
  4. Measure: Net Sales. Aggregation: Sum.
  5. Temporality: Over time.
  6. Time dimension: Order Date.
  7. Adjustable metric filters: add Region, City and Category. At least one is required. These first filters also become the dimensions Pulse looks at for insights, so pick the ones a manager would ask about.
  8. Number format: currency or number with two decimals. The rupee sign may not be offered as a default currency on your site; a plain number is fine for a first build.
  9. On the Insights tab set Value going up is to favourable. Leave the insight types on.
  10. Check the previews on the right, then select Save Definition. Pulse creates the definition and an initial metric with no filters and lists it under Browse Metrics.

3. Follow the metric and set the digest

  1. Open the new Net Sales metric and select Follow.
  2. Select your user icon at the top right of Pulse and open Preferences.
  3. Choose Email (and Slack if your administrator has connected a Slack workspace) and a frequency: daily, weekly or monthly. Select Save.
  4. To make a second metric for one region, open the metric, select Filter, set Region to West and select the check mark. Follow that one too.

4. Set the time range the data can answer

Pulse measures against today's date. This file stops on 29 September 2026, so "month to date" in October shows nothing. On the metric, set the time range to the last full quarter. The label may read Last quarter or Previous quarter. In October to December 2026 that is July to September and the comparison period is April to June.

If you read this in 2027, shift the dates forward before you publish. This standard-library script moves every order by whole quarters, so April to June stays one quarter and July to September stays the next:

import csv, datetime as dt

QUARTERS = 1  # how many quarters to move forward
rows = list(csv.DictReader(open("first-pulse-metric-net-sales.csv")))
for r in rows:
    d = dt.date.fromisoformat(r["order_date"])
    m = d.month - 1 + 3 * QUARTERS
    r["order_date"] = d.replace(year=d.year + m // 12, month=m % 12 + 1, day=min(d.day, 28)).isoformat()
with open("first-pulse-metric-net-sales-shifted.csv", "w", newline="") as f:
    w = csv.DictWriter(f, fieldnames=rows[0].keys())
    w.writeheader()
    w.writerows(rows)

It clamps days to the 28th, which moves a handful of month-end orders by a day or two and never across a quarter boundary.

Check it worked

Never trust the first number a metric shows. Build the same total in Desktop from the same file and compare. With the time range on July to September 2026:

Q3 has 55 orders. Bengaluru (ST-003) is the top store in Q3 at 40,872.00, ahead of Delhi (ST-019) at 32,640.90 and Pune (ST-014) at 29,266.75. In Q2 Pune led at 68,235.25.

Pulse should flag the fall and point at West and North as the main contributors. If it points somewhere else, look at the dimensions you listed as adjustable filters first. Pulse only explains movement across the dimensions you gave it.

If your quarter total is 156,269.85 or close to it, you published the raw harbour-goods-orders.csv instead. That file keeps a duplicated order, a negative quantity, an unknown store and a date that does not exist, on purpose, for the data cleaning lessons.

Where this breaks

  • Pulse is missing from the navigation. Pulse is off for the site, or on for a group you are not in.
  • No digest arrives. Digests go to the email address on your Tableau account and arrive on the schedule you set, weekly by default. The written AI summary needs the separate AI setting and, per the help pages, two or more followed metrics.
  • A definition on a live file connection. It publishes, then never refreshes. Use an extract and a refresh schedule, or a database connection.
  • Calendar mismatch. Pulse thinks in calendar periods unless you set a custom calendar. If finance closes the quarter on a different date, the two numbers will never agree and both will be right.
  • Two definitions of the same thing. Anyone who can publish can define Net Sales again with a different filter. Use the Certified definition toggle on the one you stand behind; it needs the Create Metric Definitions permission on the data source.

On the brewhouse floor

The same pattern fits hectolitres packaged per week. Publish the packaging log as an extract, define one metric on volume with line and beer brand as adjustable filters. The packaging manager follows it. When a line goes down for a day the Monday digest says so before the weekly meeting does. Pulse will tell you volume fell on line 2; it will not tell you the filler bowl was being descaled. My executive KPI scorecard uses Pulse digests the same way.
