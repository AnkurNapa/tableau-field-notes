Maps with geographic roles: symbol, filled and unknown places

Give a field a geographic role and Tableau can put it on a map. Build a symbol map of store sales and a filled map by state, fix the places Tableau does not recognise and keep latitude and longitude as the fallback.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 1 Ankur Napa DesktopCertification

Short answer

Tableau maps a field when it has a geographic role: City, State/Province, Country/Region, Postcode and a few more. Assign the role from the Data pane, double-click the field and Tableau draws a map from its own built-in place names. Use a symbol map (sized circles at points) for totals and a filled map (shaded areas) for rates or shares. When a name does not match, Tableau shows an "unknown" count in the corner of the view. Fix it with Map > Edit Locations. Keep latitude and longitude columns in your data as the fallback that always works.

What you will build

Two maps for Harbour Goods, the fictional retailer used across this site:

  1. A symbol map with one circle per store city, sized by sales.
  2. A filled map shading each state by its sales.

You will join two files. The orders are the shared harbour-goods-orders.csv: 60 rows from July to September 2026. The locations are maps-geographic-roles.csv: one row per store with city, state, country, region, latitude and longitude. The coordinates are approximate city points chosen for the walkthrough, not store addresses.

Before you start

  • Tableau Desktop, any edition. Map tiles load from the internet, so you need a connection.
  • Save both CSVs in the same folder, so Tableau lists them together.
  • The Sales calculation from Your first workbook.
  • Three words. A geographic role tells Tableau a field holds place names it should look up. Geocoding is the look-up itself: turning a name into a point or a shape. A relationship links two tables on a shared field, here Store Id, without flattening them into one.

Steps

1. Connect and relate the two files

  1. Select Connect > To a File > Text file and open harbour-goods-orders.csv.
  2. On the data source page, the left pane lists the other files in the folder. Drag maps-geographic-roles.csv onto the canvas next to the orders table.
  3. A line, the relationship, joins the two. Tableau opens a panel to set the matching fields. Check that it reads Store Id = Store Id. If Tableau picked something else, change both sides to Store Id.
  4. Open Sheet 1 and create the Sales calculated field:
[Quantity] * [Unit Price] * (1 - [Discount])

2. Assign geographic roles

  1. In the Data pane, expand the locations table. Tableau may already show a small globe beside City, State and Country. That globe means a geographic role is set.
  2. If City has no globe, select the Abc icon beside it and pick Geographic Role > City.
  3. Do the same for State (State/Province) and Country (Country/Region).
  4. Check Latitude and Longitude. Tableau usually assigns their roles from the names. If not, use Geographic Role > Latitude and Longitude. These roles only work on number fields.
  5. Notice two new measures in the Data pane: Latitude (generated) and Longitude (generated). Tableau adds them once any field has a role. They are its own coordinates for the place names.

3. Build the symbol map

  1. Double-click City. Tableau puts Longitude (generated) on Columns, Latitude (generated) on Rows and City on Detail. Dots appear over India.
  2. Look at the bottom right of the view. If an indicator shows a number of unknown locations, go to step 4 before you continue.
  3. Drag Sales to Size on the Marks card. Bigger circle, more sales. Drag Store Name to Label.
  4. Change the Marks card dropdown from Automatic to Circle if Tableau chose another shape.

4. Fix unknown or ambiguous places

Tableau's City role covers cities worldwide with a population of 15,000 or more. Matching still fails for two reasons.

  • Unrecognised. Tableau does not know the spelling. Older and newer city names, such as Bengaluru and Bangalore, are the usual culprits in Indian data.
  • Ambiguous. The name exists in more than one place. There is a Delhi in India and more than one in the United States.

To fix either:

  1. Select the unknown indicator at the bottom right and choose Edit Locations. If there is no indicator, use Map > Edit Locations.
  2. Under Geographic Roles, set Country/Region to From field and pick Country. That alone resolves most ambiguous cities.
  3. In the Match Values to Locations list, any row still marked Unrecognized can be fixed by selecting the cell and typing a name Tableau knows, or by choosing Enter Latitude and Longitude.
  4. Select OK.

One more unknown is not a geocoding problem. ST-099, the store ID that is not in the Harbour Goods registry, has no row in the locations file. Its sales have no city at all. Depending on your version it shows as a null or unknown location. Filter it out, or better, fix it at the source.

5. Build the filled map

  1. Create a new sheet. Double-click State. Tableau draws dots or shapes depending on the version.
  2. Set the Marks card dropdown to Map. The states fill.
  3. Drag Sales to Color. Darker means more sales.
  4. If a state stays empty, check the unknown indicator. Delhi is the one to watch: Tableau may expect a different name for the National Capital Territory. Use Edit Locations to match it to whatever name Tableau offers.

6. The latitude and longitude fallback

If geocoding fights you, plot your own coordinates. Create a sheet, drag Longitude to Columns and Latitude to Rows, then drag Store Id to Detail. Tableau draws a point per store from your numbers, with no name matching at all. It is the most reliable map in this walkthrough and the one I use for any site list.

On the filled map, Maharashtra is darkest at ₹51,645.10, because it holds two stores. Bengaluru is the biggest circle on the symbol map.

Where this breaks

  • Filled maps of totals mislead. Maharashtra is darkest because it has two stores, not because its stores sell more. A filled map suits a rate or a share: sales per store, discount rate, growth. Use a symbol map for raw totals.
  • Big areas shout. A large state with a small number looks more important than a small one with a big number. Readers see area first.
  • Offline maps. Background map tiles come from a map service. With no internet the view may show points on a blank background.
  • Too many points. Thousands of overlapping circles hide each other. A Density mark type (a heat map of where points cluster) is better. The exam lists it as a chart type to know.
  • Custom areas. Sales territories or delivery zones are not in Tableau's place list. Group states into territories, or bring a spatial file. Both are beyond a first map.

Which chart when

A map is right only when location is the question. If the question is "which store sold most", a sorted bar answers it faster. The site's chart chooser walks through the choice.

On the brewhouse floor

A brewery's distribution map is the same build. The account list carries the town and state for each bar or shop that pours the beer. The depletions file carries litres sold. A symbol map sized by litres shows where the beer actually moves. A filled map shaded by growth shows which states are warming up. Ask the sales team for each account's coordinates once, because half the outlets will sit in towns too small for Tableau's place list. I worked a fuller version of this in Mapping beer sales by market.
