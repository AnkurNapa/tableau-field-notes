Pivots, aggregates and calculations in Prep

Turn a wide weekly stock sheet into rows, add a fixed LOD for each store's weekly total, aggregate to one row per product and rank the top three per store, all inside one flow.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa PrepLOD

Short answer

Most spreadsheets arrive wide: one row per thing and one column per week. Tableau wants them tall: one row per thing per week. In Prep a Pivot step does that with a wildcard, so next month's new column is picked up without editing the flow. After that, Prep gives you three tools that look like Desktop but behave differently. A FIXED LOD in Prep writes a value onto every row. An Aggregate step collapses rows and throws away every field you did not group or aggregate. A rank calculation partitions and orders rows inside the flow. Prep allows only one of these per calculation: you cannot divide by an LOD in the same expression, so you build it in two fields.

What you will build

One flow that answers a stock question for Harbour Goods: which three products does each store hold most of, on average, over the last four weeks and what share of each store's week does each product take?

The input is prep-pivots-aggregates-lod-rank.csv, a synthetic stock count with 54 rows (six stores times nine products) and four week columns, wk36 to wk39, holding units on hand at the end of each week in September 2026. It looks like this:

ST-003P-102103711

You will join harbour-goods-products.csv at the end for product names.

Before you start

  • Tableau Prep Builder 2020.1.3 or later for FIXED LOD and rank calculations. Any current version is fine.
  • The Your first Prep flow walkthrough, or the same comfort with Input, Clean and Output steps.

Steps

1. Pivot the week columns to rows

  1. Connect the stock CSV with Connect to Data > Text file.
  2. Select the plus icon on the Input step and choose Pivot.
  3. In the Pivoted Fields pane, check the drop-down at the top reads Columns to Rows.
  4. Select Use wildcard search to pivot, type wk and press Enter. All four week columns move into the pivot.
  5. Rename the two new fields. The names field (it usually reads Pivot1 Names) becomes week. Pivot1 Values becomes on_hand.
  6. Rename the step Pivot weeks.

The wildcard is the point. When the October file arrives with wk40 to wk43, the same flow picks them up. Dragging four named fields into the pivot would quietly ignore every new week.

2. Add a fixed LOD for the store's weekly total

  1. Add a Clean Step after the pivot and name it Store share.
  2. On the on_hand card, open the More options menu and select Create Calculated Field > Fixed LOD.
  3. In the visual editor, choose store_id and week as the fields to group by (the label may read Group by), set the computation to SUM of on_hand and name the result store_week_units.

The same thing typed in the calculation editor:

{FIXED [store_id], [week] : SUM([on_hand])}

Now create a second, ordinary calculated field called share_of_store_week:

[on_hand] / [store_week_units]

Prep does not accept [on_hand] / {FIXED [store_id], [week] : SUM([on_hand])} in one field. Combining an LOD with another expression is not supported and neither is nesting. Two fields is the pattern and it also leaves store_week_units visible for checking.

3. Aggregate to one row per store and product

  1. Add an Aggregate step after Store share.
  2. Drag store_id and product_id to Grouped Fields.
  3. Drag on_hand to Aggregated Fields. It defaults to SUM; select the aggregation and change it to AVG. Rename it avg_on_hand.

Every field you did not drag in is gone after this step, including week, store_week_units and share_of_store_week. That is by design. If you need the share later, branch the flow after Store share and send that branch to its own output.

4. Rank products inside each store

  1. Add a Clean Step after the Aggregate step and name it Rank.
  2. On the avg_on_hand card, open More options and select Create Calculated Field > Rank.
  3. Group by store_id, order by avg_on_hand and keep the rank function as RANK. Name the field stock_rank. The editor labels may differ slightly between versions.

In the calculation editor it reads:

{PARTITION [store_id] : {ORDERBY [avg_on_hand] : RANK()}}

Prep orders descending by default, so the largest average gets rank 1. Add ASC after the field to reverse it. RANK gives tied rows the same number and skips the next; RANK_DENSE does not skip. ROW_NUMBER is available in the calculation editor but not in the visual one.

  1. On the stock_rank card, open More options and select Filter > Calculation, then enter [stock_rank] <= 3.

5. Add names and write the output

  1. Connect harbour-goods-products.csv and join it to the Rank step on product_id. An inner join is right here: every product ID in the stock file is in the product list.
  2. Add an Output step, save to File as Tableau Data Extract (.hyper) named top3_stock_by_store and run the flow.

Where this breaks

  • A wildcard that matches too much. wk also matches a column called wk_notes if someone adds one. Use a tighter pattern or rename the columns at the source.
  • Pivoting rows to columns is one way. In Rows to Columns mode you cannot drag fields back out to undo it. Use Undo or delete the step. Date fields must be strings before they can become column names.
  • The Aggregate step drops fields. People add one after a long Clean step and then wonder where their calculations went. Branch first.
  • LOD limits in Prep. Only FIXED. No INCLUDE or EXCLUDE, no nesting and no combining an LOD with other arithmetic in one field. Desktop allows all of these, so a calculation copied from a workbook may not paste.
  • Prep's LOD ignores dashboard filters. It is computed once when the flow runs. A share of the store's week is right for the whole store; it will not recompute when a reader filters to one category. That kind of share belongs in Desktop.
  • Do not name a field Number of Records. The help notes it causes a permission-related error in Prep.

On the brewhouse floor

A winery's cellar team often keeps barrel top-up records in a wide sheet: one row per barrel, one column per week. Pivot the weeks to rows with a wildcard, add a fixed LOD for the litres topped up per cellar per week and each barrel's share of the week's work shows which barrels are losing the most wine. Aggregate to one row per barrel, rank inside each cellar and the three thirstiest barrels per cellar are the ones to inspect first. The cellar and barrel-ageing inventory dashboard reads well from a table shaped like this.
