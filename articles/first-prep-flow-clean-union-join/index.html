Your first Prep flow: clean, union and join two order exports

Take two messy order exports, union them, fix store IDs and three date formats, remove duplicates, join the store list and write a Hyper extract. Every row count is checked.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 1 Ankur Napa Prep

Short answer

A Prep flow is a chain of steps you can see. Two inputs go into a Union step, a Clean step fixes what is wrong, a Join step adds the store details and an Output step writes a .hyper file. The order matters more than the steps. Clean the values before you look for duplicates, or Prep will tell you two copies of the same order are different rows. In this walkthrough 61 raw rows become 56 clean ones and you will know where every one of the five went.

What you will build

One flow, saved as harbour_orders_q3.tfl, that turns two quarterly order exports from Harbour Goods into one extract called harbour_orders_q3.hyper.

The files are deliberately messy, the way till exports usually are:

  • first-prep-flow-orders-jul-aug.csv: 39 rows for July and August.
  • first-prep-flow-orders-sep.csv: 22 rows for September. Its quantity column is called qty, not quantity.
  • harbour-goods-stores.csv: the six known stores with city and region.

What is wrong with them, counted in Python before writing this:

ProblemRows affected
order_date in three formats: 2026-07-02, 06/07/2026 and 11 Jul 202632 ISO, 22 day/month/year, 7 day month-name year
store_id in lower case or with a trailing space, such as st-014 or ST-003 15
Exact duplicate rows, the same order exported twice4 (three inside a file, one in both files)
A duplicate that only matches once dates and store IDs are cleaned1
Store ST-099, which is not in the store list2

The September export also repeats the last August order, HG-41036. Export windows overlap. Somebody ran the August file at noon on the last day and the September file picked up the same order. That is the duplicate that sits in both files.

Before you start

  • Tableau Prep Builder 2024.1 or later. The Identify Duplicate Rows feature arrived in 2024.1. Prep Builder comes with the Creator licence; a trial works for this walkthrough.
  • Windows or Mac. The menus below are the same on both unless noted.
  • The three CSV files saved in one folder.

Steps

1. Connect both order files

  1. Open Prep Builder and select Connect to Data (the plus button in the Connections pane) > Text file.
  2. Choose first-prep-flow-orders-jul-aug.csv. An Input step appears in the Flow pane.
  3. Repeat for first-prep-flow-orders-sep.csv.
  4. Select the first Input step. In the Input pane, find order_date in the field list. If its type shows as Date, select the type icon and change it to String. Do the same in the second input.

That last step is the one people skip. Prep infers a type from a sample of rows. If it decides order_date is a date, the values in the other formats can arrive as nulls before you have seen them. Keep the column as text and parse it yourself.

2. Union the two inputs

  1. Drag the September Input step onto the July and August one until Union appears, then drop it.
  2. Select the Union step. The Union pane lists both tables and a Mismatched Fields list. quantity and qty are shown apart.
  3. Select qty, then hold Ctrl (Command on Mac) and select quantity. Right-click and choose Merge Fields. Rename the result quantity if Prep kept the other name.

The union now has 61 rows. Prep also adds a field that records which input each row came from (it usually reads Table Names). Keep it for now; it is useful when you trace a bad row.

You could also union the files in the first Input step with Union multiple tables on the Tables tab. That suits a folder of files with the same columns. Here the column names differ, so the Union step is clearer.

3. Clean the store IDs

  1. Select the plus icon on the Union step and add a Clean Step. Name it Clean values.
  2. In the Profile pane, open the More options menu (the three dots) on the store_id card.
  3. Select Clean > Trim Spaces.
  4. Select Clean > Make Uppercase.

The store_id card now shows seven values: the six real stores and ST-099. Leave ST-099 alone. Hiding it here would hide a question someone needs to answer.

4. Parse the three date formats

In the same Clean step, open the More options menu on any card and select Create Calculated Field. Name it order_day:

IFNULL(
  IFNULL(
    DATEPARSE("yyyy-MM-dd", [order_date]),
    DATEPARSE("dd/MM/yyyy", [order_date])
  ),
  DATEPARSE("dd MMM yyyy", [order_date])
)

Each DATEPARSE returns null when the text does not fit its pattern, so the IFNULL chain tries them in turn. Capital MM is month; lower-case mm is minutes, a mistake that produces dates with the month stuck on January.

Then check the order_day card. It should show no null bar. If it does, filter to the nulls and read the raw order_date values; there is a fourth format. When the card is clean, remove the original order_date field and rename order_day to order_date.

5. Find and remove the duplicates

  1. Add a second Clean Step after Clean values. Name it Remove duplicates.
  2. In the Profile pane, select every field except the source field (Table Names). Ctrl-click (Command-click on Mac) to multi-select.
  3. Select Identify Duplicate Rows on the toolbar. Prep adds a field called Is Duplicate Row? with two values, Unique and Duplicate.
  4. On the Is Duplicate Row? card, select Unique, then select Keep Only on the toolbar.

Prep marks the first row of each matching group Unique and the rest Duplicate, so one copy of each order survives. You should see 5 Duplicate and 56 Unique.

Why leave out Table Names? The overlapping order HG-41036 sits in both files. Its Table Names value differs, so if you include that field Prep treats the two copies as different rows. You would keep 57 rows and double count one order.

6. Join the store list

  1. Connect harbour-goods-stores.csv as a third input.
  2. Drag it onto the Remove duplicates step until Join appears, then drop it.
  3. In the Join pane, check that the clause is store_id = store_id.
  4. Look at Summary of Join Results before you change anything. With the default inner join, 54 rows are included and the two ST-099 rows are excluded on the left.
  5. Change the join type to Left by selecting the left circle segment in the Venn diagram. All 56 rows are now kept; the two ST-099 rows have null city and region.
  6. Add a Clean Step after the join. Remove the duplicate store_id-1 field and the opened field. Create two calculated fields. Name the first region_label:
IFNULL([region], "Unmapped")

Name the second net_amount:

[quantity] * [unit_price] * (1 - [discount])

The inner join was not wrong. It was silent. A Left join plus an Unmapped label turns a missing store into a row someone can see on a dashboard and chase.

7. Output a Hyper extract

  1. Select the plus icon on the last step and add an Output step.
  2. In Save output to, choose File.
  3. Set Output type to Tableau Data Extract (.hyper) and name it harbour_orders_q3.
  4. Leave the write option as Create table.
  5. Select Run Flow.
  6. Save the flow with File > Save as harbour_orders_q3.tfl.

To share the flow with the data inside it, use File > Export Packaged Flow, which writes a .tflx with the CSVs included.

The order_date range should run from 2 July 2026 to 23 September 2026 and 56 distinct order_id values should match 56 rows. If you see 57 rows, the source field was in your duplicate check. If you see 58, the duplicates were identified before the cleaning step.

Where this breaks

  • Ambiguous dates. 06/07/2026 is 6 July here because the exports come from an Indian till system and the file only covers July to September. In a file that mixes US and Indian sources the same text means 7 June. No calculation fixes that. Ask whoever owns the export.
  • The sample hides things. Prep profiles a sample by default. On 61 rows it sees everything; on a few million it may not. Keep Only still applies to every row when the flow runs, but a value you never saw in the profile can still be wrong.
  • Duplicates that differ in one field. Identify Duplicate Rows only catches rows that match on every selected field. If an export resends an order with a corrected quantity, both rows look unique. For that, pick only order_id and decide which copy wins.
  • Merged fields with different types. If qty arrived as text and quantity as a number, the merged field shows a Change Data Type icon. Fix the type in each input first.
  • Hyper write options. A .hyper output supports Create table and Append to table only. Running this flow twice with Append doubles every row.

On the brewhouse floor

A brewery that runs two shifts often keeps two brew logs: one typed up by the morning brewer, one by the night shift. Union them and the same batch can appear twice, once as 03/09/2026 and once as 2026-09-03, with the fermenter written fv-03 by one shift and FV-03 by the other. Clean the dates and the fermenter IDs first, then check for duplicates and the hectolitres brewed stop being counted twice. A fermenter that is not in the equipment list belongs under Unmapped, not in the bin. The same habit sits under a brewery production and yield dashboard.
