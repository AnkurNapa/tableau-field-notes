One KPI, one definition across workbooks and Pulse

A design guide for keeping a metric identical in every workbook, data source and Pulse digest: where the definition lives, who owns it and how to catch drift before a board meeting does.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 4 Ankur Napa DesktopServerCloudPulseAPI

Short answer

Define each KPI once, as close to the data as you can. Make every other surface read it rather than restate it. In Tableau that usually means the calculation lives in one certified published data source, every workbook connects to that source instead of writing its own formula and the Pulse metric definition is built on the same source and the same field. Ownership matters as much as placement: one named person signs off any change. Then check for drift with the Metadata API, because someone will copy the formula into a workbook anyway.

The decision

Harbour Goods has three numbers called "Q3 sales" in circulation. All three are correct for their own definition, computed from the July to September 2026 sample:

Called "Q3 sales" inWhat it actually isValue
The finance workbookQuantity times unit price, before discount159,897.00
The regional dashboardAfter discount, on the cleaned orders153,065.80
A spreadsheet exportAfter discount, on the raw file with its duplicate, negative row, unknown store and bad date156,269.85

The gap between the first two is 6,831.20 of discount. The gap between the last two is bad rows. Nobody made an arithmetic mistake. The definitions are the argument.

For most teams the second row is the right default, with the most important KPIs pushed down to the third over time.

Reference design

Rules behind the picture:

  • One name, one formula. "Sales" alone is banned. Net Sales and Gross Sales are two KPIs with two names.
  • Clean once. Duplicates, negative quantities and unknown stores are excluded upstream, not with a filter in each workbook.
  • Describe in the field. Each KPI field carries a description: formula in words, grain, exclusions and owner. Tableau shows it in the Data pane and the Metadata API exposes it.
  • Certify the source. Certification marks the source as the one to use. Tableau Catalog, where licensed, adds data quality warnings and lineage.
  • Pulse reads the same field. A Pulse metric definition holds the data source, the measure and its aggregation, the time dimension, definition filters, adjustable filters and whether the value going up is favourable. It is the single source of truth for every metric built from it, so build it on the certified source and the Net Sales field, not on a copy.

Detect drift

Copies happen. Find them with the Metadata API on Tableau Cloud or Server:

query NetSalesEverywhere {
  calculatedFields(filter: { name: "Net Sales" }) {
    name
    formula
    datasource { name }
    downstreamWorkbooks { name projectName }
  }
}

Every result whose data source is not the certified one, or whose formula differs, is a drift. Run it monthly from a script and send the list to the KPI owner. Check the field names against the Metadata API reference for your version before scheduling it.

Questions to ask the client

  1. Which ten numbers appear in board or leadership packs? Those are the KPIs. Everything else is a measure.
  2. For each, who decides the definition when two teams disagree? A name, not a department.
  3. Is the number before or after discounts, returns, tax and cancellations? Write it down.
  4. At what grain is it true: order, day, store, month? Can it be summed across stores, or only recomputed?
  5. Where do the bad rows go today: excluded upstream, filtered per workbook or left in?
  6. Which tools besides Tableau show the number: finance spreadsheets, Pulse, a planning system? Which one wins when they disagree?
  7. How will a change to a definition be announced? What happens to last quarter's reported figure?

Review checklist

  • Every KPI has one name, one formula and one owner on record.
  • Every KPI is defined in a certified published data source or upstream, not in a workbook.
  • Each KPI field has a description with formula, grain, exclusions and owner.
  • Pulse metric definitions use the certified source and the same field.
  • The favourable direction is set correctly in Pulse.
  • Data cleaning rules are applied once, upstream.
  • A drift query runs on a schedule and someone reads its output.
  • Dashboard footers link to the definitions page.
  • Changes are versioned with a date. Past reported figures are labelled with the definition they used.

Anti-patterns

  • The heroic workbook. One analyst's workbook becomes the reference and everyone copies its calculations. It works until that analyst changes a filter.
  • Same name, different formula. "Sales" meaning gross in finance and net in retail. Rename until each name has exactly one meaning.
  • Fixing data in the view. A filter that drops the duplicate order in one workbook, but not in the others.
  • Pulse on a side copy. A metric definition built on an extract someone published for speed, which drifts from the certified source within a month.
  • Multi-fact sources in Pulse without testing. Tableau's help notes Pulse may not work on multi-fact relationship sources. Test before promising it.
  • Definition by meeting. Agreed in a room, never written into the field description, forgotten by the next quarter.

On the brewhouse floor

Ask three people in a brewery for last month's volume and you can get three answers: hectolitres brewed, hectolitres packaged and hectolitres sold. All are true. Brewhouse yield is worse: it can be measured into the kettle, into the fermenter or into package. The numbers can differ by several points. Pick one definition per name, write it into the field description and build the Pulse metric on that field. The technology is the easy part. The definitions are the argument.
