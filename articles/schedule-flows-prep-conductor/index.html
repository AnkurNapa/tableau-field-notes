Schedule flows with Prep Conductor and incremental refresh

Publish a Prep flow to Tableau Cloud, write to a published data source, add incremental refresh on a sequence column and schedule a nightly incremental run plus a weekly full one.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa PrepCloudServer

Short answer

Publishing a flow puts it on Tableau Cloud or Tableau Server, where any Creator with access can open it, edit it and run it by hand. Running it on a schedule is a separate thing called Prep Conductor. It is part of Data Management. Check that first, because Data Management is no longer sold as a stand-alone add-on: you have it if your organisation bought it earlier or holds an edition that includes it. Once scheduling works, incremental refresh lets a nightly run add only the new rows. It compares the highest value already in the output with the input and appends anything larger. That is fast and also blind to edits, so pair a nightly incremental task with a weekly full refresh.

What you will build

The order flow from Your first Prep flow, moved from CSV files to a database table so it has something new to read each night:

  • Input: a PostgreSQL table harbour.orders with the same columns as the clean output of that walkthrough, plus order_seq, a whole number the database assigns to every new order.
  • Output: a published data source called Harbour Orders in a project called Harbour Sales.
  • Two scheduled tasks: an incremental refresh at 02:00 every day and a full refresh at 03:00 every Sunday.

Why not keep the CSVs? When you publish a flow with local file inputs, the files are packaged with it. Packaged files are not refreshed when the flow runs. Tableau Cloud does not support direct file connections at all. A schedule that rereads the same packaged file every night does nothing useful. Any database Tableau Cloud can reach works here; PostgreSQL is only the example.

Before you start

  • Licences. Prep Builder comes with Creator. Only Creators (or site and server administrators) can create or edit scheduled flow tasks.
  • Data Management on your Tableau Cloud site or Tableau Server, with Prep Conductor enabled. On Tableau Cloud it is included with the Tableau+ bundle and Tableau Cloud+; on Server, with Tableau Server+ and Tableau Enterprise. Without it you can still publish, edit and run flows manually; you cannot schedule them.
  • A reachable database. Tableau Cloud must reach it directly, or through Tableau Bridge for a database inside your network.
  • Permissions to publish to the Harbour Sales project.

Steps

1. Point the flow at the database table

  1. In Prep Builder, open harbour_orders_q3.tfl and save a copy as harbour_orders_nightly.tfl.
  2. Select Connect to Data > PostgreSQL, sign in and drag harbour.orders to the Flow pane.
  3. Replace the union and the cleaning of the old inputs with this one input. In this version the database already holds clean rows; the flow keeps the store join and the region_label and net_amount calculations.

2. Turn on incremental refresh in the Input step

  1. Select the harbour.orders Input step and open the Settings tab in the Input pane.
  2. Under Incremental Refresh, tick Enable incremental refresh.
  3. Set Input field to order_seq. It must be a whole number, a date or a date and time. Only one field is allowed.
  4. Set Output to the output step you will create next and Output field to order_seq. The two fields must share a name and a type.

A sequence number is the safest choice. A date works too, but if orders for yesterday keep arriving after the run, a date-based increment never picks them up because they are not later than the maximum already stored.

3. Write to a published data source

  1. Select the Output step. In Save output to, choose Published data source.
  2. Choose the server or site, the Harbour Sales project and the name Harbour Orders.
  3. Under the write options, set the full refresh to Create table and the incremental refresh to Append to table. Published data sources support only these two.

4. Run a full refresh locally once

Open the drop-down next to the run button on the top menu and select Full refresh. An incremental run needs an existing output to compare against, so the first run is always a full one.

5. Publish the flow

  1. Select Server > Publish Flow.
  2. Choose the Harbour Sales project, name the flow Harbour orders nightly and add a description that says what it reads and writes.
  3. Under Connections, select Edit for the PostgreSQL input and choose Embedded Password. A scheduled run has nobody to answer a prompt.
  4. Select Publish. The flow's overview page opens in your browser.

6. Schedule the nightly incremental task

On Tableau Cloud:

  1. On the flow page, open the Scheduled Tasks tab and select New Task (or the drop-down and Single Task).
  2. Select Define a schedule. Choose Daily, once a day, at 02:00, on all seven days. Check the time zone; it is a site setting, not your laptop's.
  3. Keep Automatically include all output steps for this flow.
  4. Under refresh type, select Incremental refresh.
  5. Tick Send email when done if you own the flow and want to know.
  6. Select Create Task.

Then repeat with Weekly, Sunday at 03:00 and Full refresh. On Tableau Server the dialog is similar, though server administrators may have set up shared schedules for you to choose from.

When one flow feeds another, use a Linked Task instead. It runs up to 20 flows in sequence and lets you stop the rest, email yourself or add a data quality warning if one fails.

Check it worked

These numbers follow from the sample data, assuming you loaded the 56 clean orders from the first walkthrough into harbour.orders with order_seq 1 to 56. They are a worked example, not a measured run.

  1. After the first full refresh, open Harbour Orders in a new workbook. The row count is 56 and MAX(order_seq) is 56.
  2. Insert four new orders into the table:
INSERT INTO harbour.orders
  (order_seq, order_id, order_date, store_id, product_id, quantity, unit_price, discount)
VALUES
  (57, 'HG-41057', '2026-09-24', 'ST-011', 'P-104', 2, 1299, 0.00),
  (58, 'HG-41058', '2026-09-24', 'ST-003', 'P-101', 1,  699, 0.05),
  (59, 'HG-41059', '2026-09-25', 'ST-019', 'P-107', 1, 1799, 0.00),
  (60, 'HG-41060', '2026-09-25', 'ST-022', 'P-102', 3,  549, 0.10);
  1. Let the incremental task run, or run the flow from its page. Refresh the workbook: 60 rows, MAX(order_seq) 60.
  2. Run the incremental task again with no new rows. The count stays at 60. If it jumps to 64 or 120, the output write option for incremental is Create table or the input field is wrong.
  3. As a site administrator, open the Performance of Flow Runs admin view to see run durations and Background Tasks for Non Extracts to see successes and failures by task.

Where this breaks

  • Edits and deletes are invisible to incremental runs. If order 12 is corrected in the database, the appended data keeps the old value until the next full refresh. That is what the Sunday task is for.
  • Late rows on date-based increments. Covered in step 2. Use a sequence or a load timestamp if the source has one.
  • Outputs that cannot do incremental. Excel, Amazon S3, CRM Analytics and Databricks outputs do not support it. CSV outputs only support Create table. Hyper outputs, local or published, only support Append to table.
  • Expired passwords. An embedded password that expires breaks every scheduled run with an authentication error. Use a service account and update the credential on the flow's Connections tab.
  • Several outputs from one incremental input. They must run together with the same refresh type, so include all of them in the task.
  • No Data Management. The Scheduled Tasks tab may be missing or empty. Run flows by hand on the web, or from a machine with Prep Builder installed using tableau-prep-cli --incrementalRefresh -t flow.tfl on a scheduler you already have. That machine then becomes something you must look after.

On the brewhouse floor

Fermentation readings arrive all day: gravity and temperature from each fermenter, logged by hand or from a sensor. A flow that rereads every reading since the brewery opened gets slower each week. Incremental refresh on the reading's sequence number adds only last night's readings. A weekly full refresh picks up the corrections, such as the gravity reading someone typed as 1.0O5 and later fixed. The live fermentation-monitoring dashboard then reads a source that is never more than a day behind.
