Lineage with the Metadata API: what breaks when a column changes

Use GraphQL against the Tableau Metadata API to find every calculation, sheet, workbook and owner that depends on one field in a published data source, first in GraphiQL and then from Python with Tableau Server Client.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 3 Ankur Napa APICloudServerSecurity

Short answer

The Metadata API is a GraphQL endpoint at /api/metadata/graphql on Tableau Cloud and Server. It indexes how content connects: databases, tables, columns, published data sources, fields, calculations, sheets, dashboards, workbooks and their owners. To find what breaks when a column changes, start at the field in the published data source and ask for its downstreamFields, downstreamSheets, downstreamWorkbooks and downstreamOwners. One query replaces an afternoon of opening workbooks. Sign in with the REST API first; the Metadata API uses the same credentials token.

The symptom

The data team wants to rename discount to discount_rate in the Harbour Goods orders extract. Three people have already read 0.05 as five rupees. Nobody knows which dashboards would break. The usual method is to open every workbook that might use the data source and search its calculations. On a site with forty workbooks that is a day. Someone still misses one.

The site for this walkthrough has:

  • The published data source Harbour Goods Orders Extract from Build extracts with the Hyper API, built on harbour-goods-orders-clean.csv.
  • A workbook Harbour Goods Orders connected to it, with two sheets. Units by store shows SUM(quantity) by store_id. Net sales by store uses a calculated field.

The calculated field, created in the workbook with Analysis > Create Calculated Field:

// Net sales
SUM([quantity] * [unit_price] * (1 - [discount]))

Measure it

1. Open GraphiQL

Sign in to Tableau Cloud in your browser, then open:

https://<pod>.online.tableau.com/metadata/graphiql/

GraphiQL uses your browser session. The Metadata API is always on in Tableau Cloud. On Tableau Server an admin runs tsm maintenance metadata-services enable first and waits for the initial index.

2. Confirm the data source is indexed

query FindSource {
  publishedDatasources(filter: { name: "Harbour Goods Orders Extract" }) {
    name
    luid
    projectName
    hasExtracts
    owner { name }
    fields { name }
  }
}

Expect one data source in Harbour Sales with seven fields: order_id, order_date, store_id, product_id, quantity, unit_price and discount. If the list is empty, the content was published minutes ago and the index has not caught up, or your account cannot see it.

3. Ask what depends on the field

query FieldImpact($ds: [String], $field: [String]) {
  publishedDatasources(filter: { name: $ds }) {
    name
    fields(filter: { name: $field }) {
      name
      downstreamFields {
        __typename
        name
        datasource { name }
        ... on CalculatedField { formula }
      }
      downstreamSheets {
        name
        workbook { name projectName }
      }
      downstreamWorkbooks {
        name
        owner { name }
      }
      downstreamOwners { name }
    }
  }
}

In the Query Variables pane:

{ "ds": ["Harbour Goods Orders Extract"], "field": ["discount"] }

Filters in the Metadata API take lists, which is why the variables are [String] rather than String.

4. Run the same check from Python

GraphiQL is for exploring. For a pre-change check that runs every time, use Tableau Server Client, which signs in and posts the query for you:

import json
import os
import sys

import tableauserverclient as TSC

QUERY = """
query FieldImpact($ds: [String], $field: [String]) {
  publishedDatasources(filter: { name: $ds }) {
    name
    fields(filter: { name: $field }) {
      name
      downstreamFields { __typename name ... on CalculatedField { formula } }
      downstreamSheets { name workbook { name } }
      downstreamOwners { name }
    }
  }
}
"""

datasource, field = sys.argv[1], sys.argv[2]
auth = TSC.PersonalAccessTokenAuth(
    os.environ["TABLEAU_PAT_NAME"],
    os.environ["TABLEAU_PAT_SECRET"],
    site_id=os.environ["TABLEAU_SITE"],
)
server = TSC.Server(os.environ["TABLEAU_SERVER"], use_server_version=True)

with server.auth.sign_in(auth):
    result = server.metadata.query(
        QUERY, variables={"ds": [datasource], "field": [field]}, abort_on_error=True
    )

sources = result["data"]["publishedDatasources"]
if not sources or not sources[0]["fields"]:
    sys.exit(f"{datasource}.{field} not found in the Metadata API index")

impact = sources[0]["fields"][0]
sheets = sorted({(s["workbook"]["name"], s["name"]) for s in impact["downstreamSheets"]})
print(json.dumps({
    "calculations": [f["name"] for f in impact["downstreamFields"]
                     if f["__typename"] == "CalculatedField"],
    "sheets": [f"{wb} / {sheet}" for wb, sheet in sheets],
    "owners": sorted({o["name"] for o in impact["downstreamOwners"]}),
}, indent=2))
python field_impact.py "Harbour Goods Orders Extract" discount

abort_on_error=True turns GraphQL errors into a Python exception. Without it, TSC returns the error inside the result and your script carries on with half an answer.

Fix it

The query is the measurement and the fix is a habit built on it:

  1. Run the impact check before every rename or drop. Make it a required step in the change ticket for any published data source.
  2. Send the owner list to the owners. downstreamOwners is the mailing list for the change notice. Give them a date.
  3. Rename with an alias first. In the published data source, rename the field's caption to the new name and keep the underlying column. Calculations bind to the field, so they survive a caption change. Change the column in the source later.
  4. Run it again after the change. The same script with the new name should return the same calculations and sheets. If the old name still has dependants, something is pointing at a copy.

{
  "calculations": [
    "Net sales"
  ],
  "sheets": [
    "Harbour Goods Orders / Net sales by store"
  ],
  "owners": [
    "<your display name>"
  ]
}

The useful line is the second sheet that is not there. Units by store uses quantity only, so it is safe. Lineage tells you what you do not need to test as well as what you do.

Run the same script with quantity and both sheets appear, because Net sales also uses quantity.

Where this breaks

  • The index lags. The Metadata API indexes in the background. Content published a few minutes ago may not be there yet. Do not run the check straight after a publish.
  • You only see what you can see. Results respect permissions. An analyst running the check will miss workbooks in projects they cannot open. Run it with a site admin's token, kept for this job only.
  • Big queries return partial results. Very wide queries can hit the node limit or the time limit. The API then returns data with a NODE_LIMIT_EXCEEDED or TIME_LIMIT_EXCEEDED warning. Treat any warning as "answer incomplete". Narrow the filter or page with the ...Connection fields (first, after), up to 1,000 items a page.
  • Copies break the chain. A workbook connected to a local copy of the CSV, not the published data source, has no lineage to it. The query cannot find dependants that never connected.
  • Catalog is a separate licence. The Catalog lineage pages in the web UI need the Data Management licence. The Metadata API docs do not say the API needs it. Check what your own site returns before you promise anyone a lineage dashboard.
  • Custom SQL hides columns. Columns referenced inside custom SQL can show as a CustomSQLTable rather than as named columns. Lineage through hand-written SQL is only as good as Tableau's parse of it.

On the brewhouse floor

A winery renames brix to brix_at_harvest because the cellar team also logs Brix during fermentation and the two keep getting mixed up. Before anyone touches the harvest data source, the lineage query lists the ripeness curve calculation, the three sheets that use it and the two people who own them. The rename goes out with a note to exactly those two people. The vintage report still works on the morning the winemaker opens it. My vineyard yield and harvest dashboard has that kind of Brix field at its centre.
