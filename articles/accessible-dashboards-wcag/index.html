Accessible dashboards: contrast, keyboard and screen readers

Audit a published Tableau dashboard against WCAG 2.2 AA and Tableau's own accessibility guidance, measure contrast and marks, fix what fails and keep a record that proves it.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 3 Ankur Napa DesktopServerCloudDesign

Short answer

Tableau says you can build dashboards that conform to WCAG 2.2 AA. It does not say every dashboard does. Conformance comes from choices: simple charts with under 1,000 marks, text that explains each view, colour that meets contrast ratios and is never the only signal, filters of the supported kinds, a sensible order of objects and an embed page that is itself accessible. Interactivity inside a view, such as selecting marks and reading tooltips, is not accessible, so nothing a reader needs may live only there. Measure each of these, fix what fails and write the results down.

The symptom

The Harbour Goods store performance dashboard has drawn a complaint. A store manager who uses a screen reader cannot tell which stores missed target. A colleague with colour vision deficiency cannot tell the orange Kitchen bars from the red Home bars. Nobody can reach the store filter from the keyboard on the published page.

The dashboard has a bar chart of sales by store and category in the default Tableau 10 palette, a red and green status column, a range slider for date, light grey axis text, values only in tooltips and an order detail table with every row.

Measure it

Run five checks and record each result.

1. Contrast

WCAG 2.2 sets two ratios that matter for dashboards. Success criterion 1.4.3 Contrast (Minimum) asks for 4.5 to 1 for normal text and 3 to 1 for large text. Success criterion 1.4.11 Non-text Contrast asks for 3 to 1 for graphical objects a reader needs to understand the content, such as bars and lines, against the colours next to them.

2. Use of colour

WCAG 1.4.1 Use of Color says colour cannot be the only way to convey information. The red and green status column fails it outright. Check every legend: is there a label, a shape or a position that carries the same meaning?

3. Marks

The status bar at the bottom of Tableau Desktop shows the mark count for each sheet. The store by category chart has 21 marks. The order detail table has 55 rows times its columns. On real data it would be thousands. Tableau renders views over 1,000 marks on the server. Server-rendered views are not supported for WCAG conformance.

4. Keyboard and reading order

Publish to Tableau Server or Tableau Cloud and use the view with the keyboard only. Tab and Shift+Tab move between components; Enter or Space activates them. Tableau's Skip to Content control jumps past the toolbar. Note every control you cannot reach and every place focus disappears. WCAG 2.1.1 Keyboard, 2.4.3 Focus Order and 2.4.7 Focus Visible apply. WCAG 2.2 added 2.4.11 Focus Not Obscured (Minimum): a focused control must not be hidden behind something else, such as a sticky banner on the embed page.

Screen readers read dashboard objects in the order they were added, not the order they appear on screen. Listen to the dashboard with NVDA, JAWS or VoiceOver and write down the order you hear.

5. Text and controls

List every view without a title or caption, every legend or filter with a field name as its heading and every value that appears only in a tooltip. Note the date range slider: Tableau supports single-value and multiple-value filters, as a list or a drop-down, for conformance. A slider is not on that list.

Fix it

  • Colour. Replace the Kitchen orange and the yellow highlight. A dark blue #1F4E79 (8.66 to 1) and a burnt orange #B35C00 (4.72 to 1) both pass for bars and text on white. Use Tableau's colour-blind palette as a starting point and pick colours that differ in lightness, not only in hue.
  • Status. Replace red and green with a text label, "Above target" or "Below target", or a shape plus the label. The colour can stay as a second signal.
  • Values. Add mark labels to the bar chart so the numbers are on the bars, not only in tooltips.
  • Marks. Replace the order detail table with a summary by store and category. If the detail must exist, put it on its own sheet and keep it under 1,000 marks with a filter.
  • Text. Give every view a title that says what it shows and a caption that states the finding in a sentence. Rename legend and filter headings to say what they control, for example "Colour key for product category". Use plain words, not all capitals and no "image of" at the start of a description.
  • Alt text. Recent versions generate alt text for each view and let you edit it. Read what Tableau wrote and add the context a reader needs.
  • View Data. Leave it on. It gives screen-reader users a table of the underlying values.
  • Filters. Swap the date slider for a single-value drop-down of months.
  • Reading order. Rebuild the dashboard adding objects in the order they should be read: title, summary text, filters, main chart, supporting chart. Tableau's guidance points to editing the dashboard XML as the only other way to change it, which is not worth the risk on a shared workbook.
  • Publishing. Embed in a page that itself meets WCAG 2.2 AA. Turn off Web Edit for the audience and hide the Custom Views, Subscriptions and Alerts toolbar buttons, as Tableau's guidance asks.
  • Target size. WCAG 2.2 criterion 2.5.8 Target Size (Minimum) asks for pointer targets of at least 24 by 24 CSS pixels, or enough spacing. Check any custom buttons or navigation images on the dashboard.

Store the table, the palette hex codes and the screen reader reading order with the workbook. An accessibility claim without evidence is a hope.

Where this breaks

  • Tooltips and selection. Tableau states that interactivity within a view is not accessible. A dashboard whose story depends on hover cannot conform. Put the story in text.
  • Web editing. Conformant views do not support web editing. Readers who need to edit get a separate route.
  • Tableau Public. Tableau's dashboard accessibility guidance names Tableau Server and Tableau Cloud. Do not promise WCAG conformance for a Public embed on its say-so.
  • Dense charts. A scatter of every order or a map of every postcode will cross 1,000 marks. Aggregate first.
  • The embed page. A conformant view inside an inaccessible page still fails the reader. Own the whole page or audit it with the site team.

On the brewhouse floor

A quality dashboard in a brewery often shows fermentation tanks as green, amber and red. A brewer with red-green colour vision deficiency, which affects roughly one man in twelve, sees two of those as nearly the same. Add the status word to each tank and a shape for "out of spec". The night shift reading it on a tablet in a dim cellar benefits too: high contrast is easier for everyone at 3 a.m.
