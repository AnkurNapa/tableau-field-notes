Automate with Tableau Server Client: publish, permission and refresh

One Python script with Tableau Server Client that creates a locked project, creates a group, sets project and default permissions, publishes a workbook and runs an extract refresh it waits for. Safe to run twice.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa APICloudServerSecurity

Short answer

Tableau Server Client (TSC) is the Python library over the REST API. Install tableauserverclient, sign in with a personal access token inside a with block and every endpoint hangs off the server object: server.projects, server.groups, server.workbooks, server.datasources, server.jobs. Publishing is server.workbooks.publish(item, file, mode). Permissions are lists of PermissionsRule objects. A refresh returns a job and server.jobs.wait_for_job() blocks until it finishes or raises JobFailedException. Write the script so a second run changes nothing it does not have to.

What you will build

harbour_deploy.py, about 90 lines, that does five things against your sandbox:

  1. Finds or creates a top-level project called Harbour Sales with permissions locked to the project.
  2. Finds or creates a group called Store Managers.
  3. Gives that group view on the project, view and filter on its workbooks and connect on its data sources.
  4. Publishes Harbour Goods Orders.twbx into the project, overwriting the old copy.
  5. Optionally refreshes a named extract and waits for the job.

The workbook is the units-by-store view from earlier steps, saved as a packaged workbook from Tableau Desktop, built on harbour-goods-orders-clean.csv.

Before you start

  • A site and a PAT. Your developer sandbox and the rest-first-call token from Sandbox and your first REST call work. Creating groups and projects needs a site admin role. Give automation its own PAT, named for the job.
  • Python 3.10 or later. TSC 0.41, the current release on PyPI, needs it.
  • The packaged workbook. In Tableau Desktop select File > Save As and choose Tableau Packaged Workbook (*.twbx). Save it next to the script as Harbour Goods Orders.twbx.

Steps

1. Install TSC in a virtual environment

python3 -m venv .venv && source .venv/bin/activate
pip install --upgrade tableauserverclient
python -c "import importlib.metadata as m; print(m.version('tableauserverclient'))"

Expect 0.41 or later.

2. Set the environment

export TABLEAU_SERVER="https://<pod>.online.tableau.com"
export TABLEAU_SITE="<site-content-url>"
export TABLEAU_PAT_NAME="harbour-deploy"
read -rs TABLEAU_PAT_SECRET && export TABLEAU_PAT_SECRET

3. Write the script

"""Publish the Harbour Goods workbook, set permissions and refresh an extract."""
import os
import sys

import tableauserverclient as TSC
from tableauserverclient.server.endpoint.exceptions import JobFailedException

PROJECT = "Harbour Sales"
GROUP = "Store Managers"
WORKBOOK_FILE = "Harbour Goods Orders.twbx"
WORKBOOK_NAME = "Harbour Goods Orders"
REFRESH_DATASOURCE = os.environ.get("REFRESH_DATASOURCE")  # optional

Allow = TSC.Permission.Mode.Allow
Cap = TSC.Permission.Capability


def get_or_create_project(server: TSC.Server) -> TSC.ProjectItem:
    for project in server.projects.filter(name=PROJECT):
        if project.parent_id is None:
            return project
    item = TSC.ProjectItem(name=PROJECT, content_permissions="LockedToProject")
    return server.projects.create(item)


def get_or_create_group(server: TSC.Server) -> TSC.GroupItem:
    found = server.groups.filter(name=GROUP)
    if len(found) > 0:
        return found[0]
    return server.groups.create(TSC.GroupItem(GROUP))


def set_permissions(server, project, group) -> None:
    grantee = TSC.GroupItem.as_reference(group.id)
    server.projects.update_permissions(
        project, [TSC.PermissionsRule(grantee, {Cap.Read: Allow})]
    )
    server.projects.update_workbook_default_permissions(
        project,
        [TSC.PermissionsRule(grantee, {
            Cap.Read: Allow, Cap.Filter: Allow, Cap.ViewComments: Allow,
            Cap.AddComment: Allow, Cap.ExportImage: Allow,
        })],
    )
    server.projects.update_datasource_default_permissions(
        project, [TSC.PermissionsRule(grantee, {Cap.Read: Allow, Cap.Connect: Allow})]
    )


def main() -> int:
    auth = TSC.PersonalAccessTokenAuth(
        os.environ["TABLEAU_PAT_NAME"],
        os.environ["TABLEAU_PAT_SECRET"],
        site_id=os.environ["TABLEAU_SITE"],
    )
    server = TSC.Server(os.environ["TABLEAU_SERVER"], use_server_version=True)

    with server.auth.sign_in(auth):
        project = get_or_create_project(server)
        group = get_or_create_group(server)
        set_permissions(server, project, group)

        wb = server.workbooks.publish(
            TSC.WorkbookItem(project.id, name=WORKBOOK_NAME, show_tabs=False),
            WORKBOOK_FILE,
            mode=TSC.Server.PublishMode.Overwrite,
        )
        print(f"Published workbook {wb.name} ({wb.id})")

        if not REFRESH_DATASOURCE:
            return 0
        matches = server.datasources.filter(name=REFRESH_DATASOURCE)
        if len(matches) == 0:
            print(f"No data source called {REFRESH_DATASOURCE}", file=sys.stderr)
            return 1
        job = server.datasources.refresh(matches[0])
        try:
            job = server.jobs.wait_for_job(job, timeout=900)
        except JobFailedException as err:
            print(f"Refresh failed: {err}", file=sys.stderr)
            return 1
        print(f"Refresh finished at {job.completed_at}")
    return 0


if __name__ == "__main__":
    sys.exit(main())

A few choices worth naming:

  • filter(name=...) runs on the server. It does not download every project and search in Python.
  • parent_id is None keeps the script from matching a nested project that happens to share the name.
  • LockedToProject means workbooks published here take the project's default permissions and owners cannot loosen them. That is why the script sets defaults rather than permissions on each workbook.
  • PublishMode.Overwrite makes the publish repeatable. CreateNew fails on the second run.
  • wait_for_job polls with a back-off. The timeout stops a stuck refresh holding a scheduler slot forever.

4. Run it

python harbour_deploy.py

To include a refresh, name an extract whose source Tableau Cloud can reach:

REFRESH_DATASOURCE="<extract-name>" python harbour_deploy.py

5. Run it again

Run the same command a second time. It should find the project and the group, reapply the same rules and overwrite the workbook. No duplicate project, no duplicate group, no error.

Check it worked

  • The first run prints Published workbook Harbour Goods Orders (<id>) and exits with code 0 (echo $?).
  • In Tableau Cloud, Explore shows Harbour Sales at the top level. Open it and select Actions > Permissions. The label may read Permissions or Manage Permissions. It shows Locked content permissions and a rule for Store Managers.
  • The workbook rule for Store Managers shows View, Filter, View Comments, Add Comments and Download Image/PDF as allowed. Everything else is unspecified.
  • Open the workbook. The units-by-store view still shows 103 units across six stores, with ST-003 highest at 29.
  • After the second run the workbook's Revision History shows two revisions, if revision history is on for the site.
  • With a refresh, the script prints Refresh finished at with a UTC timestamp and the job appears under Jobs in Admin Insights or Site Status.

Where this breaks

  • Nothing to refresh. An extract built from an uploaded CSV or a published .hyper file has no live connection, so the refresh job fails. Republish the file instead, as in Build extracts with the Hyper API. A refresh needs a cloud database, a connector Tableau Cloud supports or Tableau Bridge.
  • All Users still has access. A new project inherits a default rule for the All Users group. The script adds a rule; it does not remove that one. Decide whether you want it and delete it with delete_workbook_default_permissions if not.
  • Site role caps permissions. A Viewer in Store Managers cannot web edit, whatever the rule says. Capabilities are the intersection of site role and permission.
  • Large files. TSC switches to chunked upload above 64 MB on its own. Very large workbooks still hit the site's size limits; a published data source plus a thin workbook is the better shape.
  • Embedded credentials. If the workbook connects to a database, publishing without credentials leaves it asking every viewer for a password. Pass connections with ConnectionCredentials to publish, read from environment variables, never from the script.
  • Long jobs and short tokens. The REST credentials token lasts 240 minutes by default. A deploy that waits on many refreshes can outlive it.

On the brewhouse floor

A brewery with three sites can run this script every time the quality team signs off a new version of the packaging dashboard. One project per site, locked. One group for shift supervisors with view and filter, nothing else. The script publishes the same workbook to all three and refreshes each site's extract from the line database. Nobody hand-sets permissions at the end of a night shift, which is when they usually go wrong.
