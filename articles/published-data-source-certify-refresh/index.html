One certified data source, many workbooks

Model the Harbour Goods orders, stores and products once, publish it as a certified data source and put its extract on a refresh schedule, so every workbook starts from the same numbers.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa ServerCloudPrepCertification

Short answer

A published data source is a data model that lives on the server instead of inside one workbook. You build the joins, calculations, names and formats once. Every workbook that connects to it gets the same definitions. Change Net Sales in one place and every dashboard follows.

Two more things make it trustworthy. A refresh schedule keeps its extract current without anyone opening Desktop. A certification badge tells authors this is the source to use. Neither costs extra: certification needs no Data Management licence for a published data source.

The steps here work on Tableau Server and Tableau Cloud. Scheduling differs. I show both.

What you will build

A published data source, Harbour Sales Model, built from three files:

  • harbour-goods-orders.csv, 60 order lines
  • harbour-goods-stores.csv, six stores with city and region
  • harbour-goods-products.csv, nine products with category and unit cost

It carries two calculations, Net Sales and Gross Margin, a daily extract refresh and a certification note. Then a second workbook connects to it and gets the same totals without rebuilding anything.

Before you start

  • Desktop signed in to your site with a Creator site role.
  • A place the server can read. A refresh only works if the server can reach the files. On Tableau Server, put the three CSVs on a network share the Server's run-as account can read. Connect with the full share path, not a mapped drive letter. On Tableau Cloud, either run Tableau Bridge on a machine that can see the files or keep them in a cloud file store whose connector Tableau Cloud supports. Check the connector's help page for file types before you rely on it.
  • A project you can publish to, such as the Harbour Sales project from the Level 1 step.

Steps

1. Relate the three tables

  1. Connect to the orders file. It appears on the canvas as a logical table.
  2. Drag the stores file onto the canvas. Tableau draws a relationship. Set it to Store Id = Store Id.
  3. Drag the products file in and relate it to orders on Product Id = Product Id.

Relationships keep each table at its own level of detail. Unlike an inner join, they do not drop the ST-099 order just because no store matches it.

2. Add the shared calculations

Select Analysis > Create Calculated Field twice:

// Net Sales
[Quantity] * [Unit Price] * (1 - [Discount])
// Gross Margin
[Net Sales] - [Quantity] * [Unit Cost]

Give both a default number format (right-click > Default Properties > Number Format) so every workbook shows rupees the same way.

3. Tidy the model

  • Hide the duplicate key fields from stores and products. Authors need one Store Id, not three.
  • Group fields into folders: Order, Store, Product, Measures.
  • Add a comment to Net Sales (right-click > Default Properties > Comment): "Quantity times unit price after discount. Returns are negative."

Every minute here saves an hour of someone else guessing.

4. Extract it

On the Data Source page select Extract, then Edit. Keep Logical Tables, keep All rows and select OK. Save the workbook so the extract builds.

5. Publish the data source

  1. Select Server > Publish Data Source > Harbour Sales Model.
  2. Pick the project and set the name to Harbour Sales Model.
  3. Add a description. It shows on the data source page.
  4. Leave Update workbook to use the published data source ticked, so this workbook becomes the first consumer.
  5. If you connected to a database, set authentication to Embed password. Schedules cannot run on Prompt user.
  6. Select Publish.

6. Schedule the refresh

On Tableau Cloud: select Explore > All Data Sources, tick the source, then Actions > Refresh Extracts > Schedule a Refresh. Choose Daily, once a day at 05:00. Refresh type is Full unless you set up incremental refresh in Desktop before publishing.

On Tableau Server: open the data source, go to its Extract Refreshes tab and add a refresh. The button may read New Extract Refresh or Schedule Extract Refresh. Server admins define the list of schedules, so you pick from theirs.

Select Refresh Now once (the label may read Run Now on Server) to prove the server can reach the data.

7. Certify it

You can certify if you are a site admin, the project owner or a project leader.

  1. Select Explore > All Data Sources.
  2. On the source, open ... > Data Labels > Certification. On Server 2023.1 and earlier the item is Edit Certification.
  3. Tick Certified and add a note: "Owned by retail analytics. Refreshed daily at 05:00. Net Sales includes returns."
  4. Select Save.

8. Connect a second workbook

In a new Desktop workbook select Data > New Data Source > Tableau Server and pick Harbour Sales Model. The certified badge shows next to the name. Build a bar chart of Region (discrete, blue) by SUM(Net Sales) (continuous, green).

Check it worked

The second workbook should show these totals without a single calculated field of its own:

RegionSUM(Net Sales)SUM(Gross Margin)Margin %
South58,844.4521,144.4535.9
West51,645.1019,155.1037.1
North32,640.9012,180.9037.3
East12,285.354,885.3539.8
Null854.05334.0539.1
Total156,269.8557,699.8536.9

The Null region is ST-099. A relationship keeps it, so the grand total matches the orders file. If your total is 155,415.80 someone turned a relationship into an inner join. COUNTD(Order Id) should be 59, not 60, because one order appears twice.

Then check the refresh: the data source page shows a last refresh time after your Refresh Now. On Server, a failed refresh also shows in the admin Background Tasks for Extracts view.

Where this breaks

  • The server cannot see the file. A path that works on your laptop means nothing to the server. Most first refresh failures are this.
  • Refresh time limits. Tableau Cloud cancels a single extract refresh after two hours and the limit is not configurable. Tableau Server cancels at the backgrounder.querylimit setting, 7200 seconds by default, plus a grace period.
  • Incremental needs planning. Incremental refresh must be set up in Desktop before publishing. It adds new rows by a date or rising ID column. It does not see changes to old rows unless you refresh a recent range.
  • Certification is a promise. A badge on a source nobody owns is worse than no badge. Put a named team in the note and review it each quarter.
  • Workbook calculations creep back. Authors will add their own Net Sales inside a workbook. Watch for it in reviews and move good ideas into the published source.
  • Credentials expire. Embedded database passwords and OAuth tokens expire with the account. Use a service account the source owner controls.

On the certification

This step maps to the Salesforce Certified Tableau Data Analyst exam (publishing and managing data sources) and the Tableau Server administrator credential, now Salesforce Certified Tableau Server Administrator (schedules and extracts). Check each current exam guide on Trailhead Academy.

Next on the roadmap

Once you have more than a handful of these sources, refreshes start queueing and someone asks why the 07:00 dashboard shows yesterday. That is Extracts and backgrounder load. To lock down who can see this source row by row, see Row-level security that holds.

On the brewhouse floor

Most breweries I have walked into have three versions of brewhouse yield: the brewer's, the accountant's and the one in last year's board pack. A published data source ends that argument by putting the yield calculation, the hectolitre conversion and the batch-to-tank relationship in one certified place, refreshed every morning before the production meeting. The calculation will still be argued about. At least it will be argued about once. See a brewery production and yield dashboard for the dashboard that sits on top.
