Embed a viz with the Embedding API v3 and a connected app

Put a Tableau Cloud viz in your own web page with the tableau-viz web component, then sign your users in silently with a connected app and a five-minute JWT minted on your server.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa EmbeddingAPICloudSecurity

Short answer

Embedding is two problems. The Embedding API v3 solves the first: one <script type="module"> tag and one <tableau-viz> element put a live viz in your page. A connected app solves the second: your server signs a JSON Web Token (JWT) with a secret Tableau gave you, passes it in the token attribute and Tableau Cloud trusts it instead of asking the user to sign in. The token lasts at most ten minutes, names the user in sub and carries the scope tableau:views:embed. The secret never reaches the browser.

What you will build

A local web page at http://localhost:8000 that shows the Harbour Goods Orders view from your sandbox with no sign-in prompt. A forty-line Python server mints the JWT on each page load. The view is the units-by-store bar chart built in Sandbox and your first REST call from harbour-goods-orders-clean.csv.

Before you start

  • A Tableau Cloud site where you are a site admin. Your developer sandbox works. Connected apps need an admin to create them.
  • A published view. Harbour Goods Orders, sheet Sheet 1, with store_id on Rows and SUM(quantity) on Columns.
  • A user to embed as. The JWT sub must be a user who exists on the site and can see the view. On your sandbox, that is you.
  • Python 3.10 or later with pip install pyjwt.

Steps

1. Copy the view URL

Open the view in Tableau Cloud and select Share. Copy the link. Strip anything after the sheet name so it looks like this:

https://<pod>.online.tableau.com/t/<site-content-url>/views/HarbourGoodsOrders/Sheet1

Tableau removes spaces from workbook and sheet names in the URL. That is why Harbour Goods Orders became HarbourGoodsOrders.

2. Create the connected app

  1. Select Settings > Connected Apps.
  2. Open the New Connected App drop-down arrow and choose Direct Trust.
  3. Name it harbour-embed-local.
  4. Set Applies to to Only one project and pick Default. Least access wins here: the app cannot embed anything outside that project.
  5. In Domain allowlist, allow only the domain your page runs on. For this walkthrough that is localhost.
  6. Select Create.
  7. From the actions menu next to the app, select Enable. New connected apps start disabled.
  8. Open the app. Note the client ID. Select Generate New Secret and note the secret ID and the secret value.

An app can hold two secrets at a time. That is how you rotate one without downtime.

3. Keep the secrets on the server

export TABLEAU_CA_CLIENT_ID="<client-id>"
export TABLEAU_CA_SECRET_ID="<secret-id>"
read -rs TABLEAU_CA_SECRET_VALUE && export TABLEAU_CA_SECRET_VALUE
export TABLEAU_SERVER="https://<pod>.online.tableau.com"
export TABLEAU_VIEW_URL="https://<pod>.online.tableau.com/t/<site-content-url>/views/HarbourGoodsOrders/Sheet1"
export EMBED_USER="<your-tableau-username>"

On Tableau Cloud the username is the email address you sign in with.

4. Write the server

Save this as embed_server.py:

import datetime
import html
import os
import uuid
from http.server import BaseHTTPRequestHandler, HTTPServer

import jwt

CLIENT_ID = os.environ["TABLEAU_CA_CLIENT_ID"]
SECRET_ID = os.environ["TABLEAU_CA_SECRET_ID"]
SECRET_VALUE = os.environ["TABLEAU_CA_SECRET_VALUE"]
TABLEAU_SERVER = os.environ["TABLEAU_SERVER"]
VIEW_URL = os.environ["TABLEAU_VIEW_URL"]
EMBED_USER = os.environ["EMBED_USER"]


def embed_token(username: str) -> str:
    now = datetime.datetime.now(datetime.timezone.utc)
    return jwt.encode(
        {
            "iss": CLIENT_ID,
            "sub": username,
            "aud": "tableau",
            "exp": now + datetime.timedelta(minutes=5),
            "jti": str(uuid.uuid4()),
            "scp": ["tableau:views:embed"],
        },
        SECRET_VALUE,
        algorithm="HS256",
        headers={"kid": SECRET_ID, "iss": CLIENT_ID},
    )


PAGE = """<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Harbour Goods orders</title>
  <script type="module"
    src="{server}/javascripts/api/tableau.embedding.3.latest.min.js"></script>
</head>
<body>
  <h1>Units by store</h1>
  <tableau-viz id="viz" src="{view}" token="{token}"
    width="900" height="600" toolbar="hidden" hide-tabs></tableau-viz>
</body>
</html>"""


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path != "/":
            self.send_error(404)
            return
        body = PAGE.format(
            server=html.escape(TABLEAU_SERVER),
            view=html.escape(VIEW_URL),
            token=embed_token(EMBED_USER),
        ).encode()
        self.send_response(200)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.send_header("Cache-Control", "no-store")
        self.end_headers()
        self.wfile.write(body)


if __name__ == "__main__":
    HTTPServer(("localhost", 8000), Handler).serve_forever()

Four details matter. The header carries kid (secret ID) and iss (client ID). The payload uses scp as a list; the docs warn against writing scope. Every token gets a fresh jti. Cache-Control: no-store stops a browser reusing a page that holds an expired token.

The script tag loads the library from your own Tableau Cloud pod. That keeps the library version in step with the site. The public copy at public.tableau.com also works.

5. Run it

python3 embed_server.py

Open http://localhost:8000 in a browser.

6. React when the viz is ready

The web component fires events you can listen for. Add this below the <tableau-viz> element to log when the viz is interactive:

<script type="module">
  import { TableauEventType } from "https://<pod>.online.tableau.com/javascripts/api/tableau.embedding.3.latest.min.js";
  const viz = document.getElementById("viz");
  viz.addEventListener(TableauEventType.FirstInteractive, () => {
    console.log("Viz ready:", viz.workbook.activeSheet.name);
  });
</script>

To filter on load without code, nest a filter element inside the viz:

<tableau-viz id="viz" src="..." token="...">
  <viz-filter field="store_id" value="ST-003"></viz-filter>
</tableau-viz>

Check it worked

  • The page shows six bars with no Tableau sign-in prompt.
  • The bars read ST-003 29, ST-019 20, ST-014 19, ST-011 15, ST-007 10 and ST-022 10, which is 103 units in total.
  • With the viz-filter added, one bar shows: ST-003 with 29.
  • Paste a token from the page source into a JWT decoder you trust offline. exp is five minutes after the moment you loaded the page, aud is tableau and scp is ["tableau:views:embed"].
  • Reload after six minutes. The page still works because the server mints a new token on every load.

Where this breaks

  • The viz asks for a sign-in anyway. The connected app is still disabled, the page domain is missing from the allowlist or the view sits outside the project the app applies to.
  • "Invalid JWT" errors. Most come from a server clock that is not in UTC or has drifted, an exp more than ten minutes out, scope instead of scp or a sub that is not a site user.
  • Safari or a strict browser shows nothing. Embedded sign-in can depend on third-party cookies. Test in every browser your users run, early.
  • You embed as one shared service account. Then every viewer sees the same data and Tableau logs every view against one person. Each viewer needs their own sub, or on-demand access, covered in Embedded analytics as a product.
  • The secret ends up in the browser. If JavaScript in the page can read SECRET_VALUE, anyone can mint tokens as any user. Mint on the server, always.
  • Old embed code. A page that loads tableau-2.x.js and calls new tableau.Viz() is the retired JavaScript API v2. Rewrite it with the web component rather than mixing the two.

Next on the roadmap

Automate the publishing side with Automate with Tableau Server Client. When the embed has to serve many customers with their own data, read Embedded analytics as a product. The track is on the roadmap.

On the brewhouse floor

A brewery that sells to forty bars can put a stock-and-depletions viz inside its trade ordering portal. Each bar manager signs in to the portal they already use. The portal mints a token naming that manager and they see their kegs on hand without ever meeting a Tableau sign-in screen. The brewery's sales rep sees the same chart for all forty accounts. My depletions and sell-through dashboard is the kind of view that ends up embedded this way.
