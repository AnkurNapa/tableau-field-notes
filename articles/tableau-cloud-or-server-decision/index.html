Cloud or Server: the deployment decision

Choose between Tableau Cloud and Tableau Server with a trade-off table and a list of questions, not a hunch. Most new deployments land on Cloud. The ones that should not usually know why in the first meeting.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 4 Ankur Napa ServerCloudSecurityCertification

Short answer

Choose Tableau Cloud unless a specific requirement rules it out. Cloud removes the work of patching, backing up and sizing servers. It gets new features first. Some only ever arrive there: Tableau Pulse and the Tableau+ features are Cloud only. The price of that is control. You work inside fixed capacity limits, you reach private data through Tableau Bridge and you read usage from Admin Insights instead of a database you own.

Choose Tableau Server when the requirement is real and written down: data that may not leave your network or country, an air-gapped environment, refreshes that need more than two hours, authentication Cloud does not offer or a capacity-based Core licence you already own. "We have always run it ourselves" is not on that list.

Reference design

For a typical mid-size company like Harbour Goods, with a cloud data warehouse and a few on-premises systems:

Bridge clients connect out to Tableau Cloud. Nothing on your firewall opens inbound. Run at least two clients in a pool so a patch reboot does not stop the morning refresh.

For the Server alternative, the shape is the same with the site and the Bridge pool replaced by a three-node cluster inside the network. That is the next article.

Questions to ask the client

  1. Where must the data physically live? Is there a regulator, a contract or a board decision behind that? Can I read it?
  2. Which sources sit behind the firewall, how big are they and how often must they refresh?
  3. Does any single extract take more than two hours to refresh today? How many refreshes run at the same time at peak?
  4. Which identity provider do you use? Do you need Kerberos delegation to the database, or is SAML or OIDC enough?
  5. Do you plan to use Tableau Pulse, Tableau Agent or anything else that is Cloud only?
  6. Who would patch and back up a Server? Do those people exist today? Do they want the job?
  7. What do you own already? A perpetual or Core licence changes the money, sometimes enough to decide it.
  8. How many sites do you need? Tableau Cloud Manager allows up to 3 by default, 10 on Enterprise and 50 on Tableau+.
  9. Do you embed Tableau in an external portal? How will those users sign in?
  10. If you run Server today, which repository queries and custom scripts would break on Cloud?

Review checklist

  • The data residency requirement is quoted from a document, not remembered.
  • Every on-premises source is listed with its size, refresh frequency and the Bridge pool that will serve it.
  • No extract refresh is expected to exceed two hours on Cloud, or there is a plan to split it.
  • Peak concurrent refreshes fit the edition's tenant cap, or schedules are spread.
  • SSO is designed, MFA is enforced at the identity provider and SCIM owns users and groups.
  • A named person owns the Bridge clients, including their patching.
  • Admin Insights and Activity Log replace every repository report the business relies on.
  • The licence count by role comes from real usage, not the old contract.

Anti-patterns

  • Server because it is familiar. Running Server well takes a team. If the team is one person who also builds dashboards, Cloud is cheaper in the only currency that matters: her time.
  • Cloud with one Bridge client. One Windows update and every on-premises refresh misses the morning.
  • Data residency by assumption. Teams rule out Cloud on a residency rule nobody can show them. Ask for the document.
  • Copying the Server design. Thirty sites and a script that writes to the repository do not move to Cloud. Simplify first.
  • Treating the two-hour limit as a tuning problem. An extract that needs three hours needs redesign: incremental refresh, aggregation or a live connection to a warehouse that can take the load.

Next on the roadmap

If Server wins, size it: Server topology and scaling. If Cloud wins, design sign-in and private data access: Identity, SSO and private data. If you are leaving Server, plan the move: Migrate Server to Cloud.

On the brewhouse floor

A craft brewery with one site and no IT team should run Tableau Cloud and stop thinking about it. The tank log and the brewhouse automation data usually sit on a PC in the plant office, so a pair of Bridge clients on two small machines carry them out to Cloud each morning. The day a second brewery with its own server room joins the group, ask the same ten questions again. The answer may not change. The questions keep the decision honest.
