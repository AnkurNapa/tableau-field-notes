Calculated fields with IF, CASE and ZN

Write your first row-level and aggregate calculations in Tableau: fill blanks with ZN, sort orders into bands with IF, map stores to regions with CASE and compute a discount rate that is actually right.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 1 Ankur Napa DesktopCertification

Short answer

A calculated field is a new column you define with a formula. Tableau has two kinds you need on day one. A row-level calculation runs once per row of data, like quantity times price. An aggregate calculation runs after Tableau has rolled the rows up, like SUM of one thing divided by SUM of another. Use ZN() to turn a blank number into zero, IF for ranges and CASE for exact matches. If a ratio matters, make it an aggregate. Averaging a ratio row by row gives a different and usually wrong answer.

What you will build

Five calculated fields on the Harbour Goods orders and one sheet that uses them all: sales, discount band and region for each store, with a discount rate that weighs big orders properly.

The data is the shared harbour-goods-orders.csv: 60 rows of orders from July to September 2026 for Harbour Goods, a fictional retailer. It has one blank quantity (order HG-40056) and one store ID, ST-099, that is not a real store. Both matter here.

Before you start

  • Tableau Desktop, any edition, connected to the CSV. Your first workbook shows how.
  • A few words. A function is a named operation such as ZN() or SUM(). A field reference is a field name in square brackets, such as [Quantity]. Null means "no value", which is different from zero. A string is text in quotes.
  • Every calculation starts the same way: Analysis > Create Calculated Field. You can also right-click in the Data pane and select Create Calculated Field. Type the name at the top, the formula below and select OK. The status line under the formula tells you if it is valid.

Steps

1. Fill the blank with ZN

ZN() returns the number if there is one and zero if it is Null. Create Quantity (filled):

ZN([Quantity])

Drag Quantity to Text on the Marks card and change its aggregation to Average (right-click the pill > Measure (Sum) > Average). Then do the same with Quantity (filled). The first shows 1.763 and the second 1.733. AVG skips Nulls, so the first divides by 59 rows and the second by 60. Neither is wrong. They answer different questions. You must know which one you mean.

2. Row-level Sales

Create Sales:

ZN([Quantity]) * [Unit Price] * (1 - [Discount])

This runs once per order row. Then create Gross Sales, the price before discount:

ZN([Quantity]) * [Unit Price]

The ZN means the blank row gives zero instead of Null. The totals do not change, but a Null in the middle of a longer formula can turn the whole result Null without warning. ZN at the edge stops that.

3. Discount band with IF

IF tests conditions in order and stops at the first one that is true. Create Discount Band:

IF [Discount] = 0 THEN "No discount"
ELSEIF [Discount] <= 0.05 THEN "Up to 5%"
ELSE "Over 5%"
END

It returns a string, so Tableau puts it above the line with the dimensions. Every IF needs an END. ELSE catches whatever the earlier lines missed.

4. Region with CASE

CASE compares one field with a list of exact values. It is tidier than a long IF when you are matching labels. Create Region:

CASE [Store Id]
WHEN "ST-003" THEN "South"
WHEN "ST-007" THEN "South"
WHEN "ST-011" THEN "West"
WHEN "ST-014" THEN "West"
WHEN "ST-019" THEN "North"
WHEN "ST-022" THEN "East"
ELSE "Unknown store"
END

The ELSE is the important line. Without it, ST-099 returns Null and disappears into a Null header that nobody reads. With it, the bad store shows up by name.

A CASE list like this is fine for six stores. For sixty, join the store file instead: harbour-goods-stores.csv holds the same region in a column.

5. An aggregate discount rate

Create Discount Rate:

1 - SUM([Sales]) / SUM([Gross Sales])

Every field inside is wrapped in SUM, so this is an aggregate calculation. Tableau computes it after the rows are rolled up to whatever is in the view. Right-click it in the Data pane, select Default Properties > Number Format > Percentage and set one decimal place.

Try to write [Discount] / SUM([Gross Sales]) and the status line reports that you cannot mix aggregate and non-aggregate arguments. Every field in a formula must be either inside an aggregation or outside it.

6. Put them in one view

  1. Drag Region to Rows, then Store Id to Rows to its right.
  2. Drag Sales to Columns.
  3. Drag Discount Rate to Label on the Marks card.
  4. Drag Discount Band to Color. Each store bar splits into its bands.

Check it worked

The blank-quantity row sits in "No discount" and adds nothing to Sales. Discount Rate for the whole file is 4.2 per cent. By store, ST-019 is highest at 5.6 per cent and ST-022 lowest at 2.4 per cent.

Now drag Discount onto the view as AVG(Discount). It shows 3.1 per cent. The simple average treats a one-towel order the same as a four-speaker order. The aggregate rate weighs each order by its value, which is what the finance team means by discount rate.

Where this breaks

  • Strings must match exactly. "st-003" does not match "ST-003". Use UPPER() on both sides if the source is untidy.
  • Floating point. Discount is stored as a decimal. [Discount] = 0.05 usually works, but a value like 0.0500001 from a messy source would fall through. Ranges with <= are safer than exact matches on decimals.
  • The ELSE you forgot. A CASE or IF without ELSE returns Null for anything unmatched. Nulls hide. Always write the ELSE, even if it only says "Check this".
  • Aggregate in a row-level place. Discount Rate cannot sit inside a row-level formula such as Region. On the Filters shelf it filters the rolled-up result for each mark, not the rows underneath.

Which chart when

The bar with colour bands is a stacked bar, good for parts of a whole across a few categories. When you have a different question, open the site's chart chooser.

On the brewhouse floor

Brewhouse efficiency is the classic trap. Each brew has its own efficiency. Averaging those percentages treats a 10 hL test batch like a 50 hL production brew. Write it as an aggregate instead: SUM of extract recovered divided by SUM of extract available. The result weighs every brew by its size. A CASE on the brew kit ID can label kits by site, with an ELSE that catches the kit someone typed as "BK1 " with a trailing space.
