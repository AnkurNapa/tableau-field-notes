Agentic analytics architecture: Tableau Next, semantics and MCP

A design guide for putting AI agents in front of governed Tableau data: where the definitions live, which MCP server an agent calls, how identity flows end to end and what to check before anyone outside the pilot uses it.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 4 Ankur Napa AIMCPClaudePulseSecurityCloudServer

Short answer

An agent is only as right as the definitions it reads and only as safe as the identity it runs as. Design those two things first and the choice of agent comes last. On Tableau Cloud or Server the definitions live in certified published data sources and certified Pulse metric definitions. Agents reach them through the Tableau MCP server. On Tableau Next they live in Tableau Semantics on Salesforce Data 360. Agents reach them through Agentforce, Tableau Next's own skills or the Tableau Next MCP server. In both, every request must carry the asking person's identity, row-level security must sit in the data. You also need a fixed set of questions with known answers to test the whole chain whenever something changes.

Tableau Next works alongside Tableau Cloud, Tableau Server and CRM Analytics; it is not a replacement you are forced into. It is sold standalone, inside the Tableau+ bundle or with some Salesforce editions. Data Services or Flex credits may still apply. Check the current terms with your account team; they change.

Reference design

For a Tableau Cloud customer such as Harbour Goods, with an existing Tableau estate and no Salesforce CRM:

The design rules behind the picture:

  1. One definition, many front ends. Net Sales is defined once, in the certified published data source. The Pulse definition, every workbook and every agent query read that field. Nobody writes [Quantity] * [Unit Price] * (1 - [Discount]) in a prompt.
  2. Identity end to end. The person in Slack is the person in Tableau. Row-level security by region lives in the data source, so the East manager's agent cannot see Pune whatever it is asked.
  3. A narrow, read-only door. Agents read the certified project. Writes such as publishing, moving content, user changes and refresh schedules stay with people and scripts that have a change process.
  4. Curated fields. Free text from customers or suppliers stays out of agent-facing data sources. Instructions hidden in data are the injection path no prompt can fully close.
  5. Golden questions. A fixed list of questions with expected answers, run after every data source or definition change. For Harbour Goods: net sales for July to September 2026 is 153,065.80; the top three stores are Bengaluru 40,872.00, Delhi 32,640.90 and Pune 29,266.75; West fell 46.0% from April to June. If an agent's answer drifts, the definition or the scope changed.

For a Tableau Server customer swap the access layer for a self-hosted Tableau MCP server on 2025.3 or later with OAuth, behind your own network controls, with INCLUDE_TOOLS, INCLUDE_TAGS and the file logger set. Pulse is not available, so certified data sources carry the metric definitions alone.

For a Salesforce-led customer the semantic layer moves to Tableau Semantics on Data 360. Tableau Next agents and the Tableau Next MCP server answer from the same semantic models and metrics. Published Tableau data sources can feed it. The risk to manage is two homes for one metric: decide which one is the source of truth and retire the other definition, with a date.

Questions to ask the client

  1. Where does Net Sales, or your equivalent, have exactly one definition today? Who owns it?
  2. Which data must never reach an AI model? Is it in a separate data source or only a hidden column?
  3. Is row-level security in the data or in workbook filters? Agents bypass workbooks.
  4. Which AI clients are approved: Claude, Slack, ChatGPT, Agentforce? Who controls client configuration on laptops?
  5. Tableau Cloud or Server? Which version? OAuth for self-hosted MCP needs Server 2025.3 or later.
  6. Do you hold Tableau+? Tableau Agent and some Pulse and knowledge features depend on it.
  7. Is there a Salesforce org with Data 360? Does the business want CRM and analytics definitions in one semantic layer?
  8. Which actions, if any, should an agent ever take? Who approves each one?
  9. Where do audit logs go and for how long?
  10. What are ten questions whose answers you already know and would bet your job on?

Review checklist

  • Every agent-facing data source is certified, in a locked project and has a named owner.
  • Row-level security is enforced in the data source and tested with three real user accounts.
  • Agents authenticate per user: hosted OAuth, self-hosted OAuth or direct trust with JWT_SUB_CLAIM={OAUTH_USERNAME}. No shared PAT over HTTP.
  • Tool groups are limited with INCLUDE_TOOLS or the hosted site setting EXCLUDE_TOOLS; admin, flow write and authoring tools are off.
  • Data scope is bounded with tags, projects or data source ids. Result limits are set.
  • Free-text fields are removed or replaced with categories in agent-facing sources.
  • Tool calls are logged with user, tool and arguments; logs have retention and restricted access.
  • The LLM data path is documented: Einstein Trust Layer for Tableau Agent on Cloud, your own provider on Server and each external client's terms.
  • Golden questions run weekly and after every change, with expected answers stored beside them.
  • A kill switch is documented: BREAK_GLASS_DISABLE_GLOBALLY for self-hosted, tool group exclusion for hosted.

Anti-patterns

  • The prompt as the semantic layer. Definitions pasted into system prompts drift from the data source within a month.
  • A service account behind every agent. It defeats row-level security and leaves an audit trail with one name on it.
  • Every tool on day one. The pilot needs three data source tools. Publishing and deleting can wait for a business case.
  • Two semantic layers, no owner. Tableau Semantics and Tableau Cloud data sources both define Net Sales slightly differently. The agents disagree in front of the board.
  • Trusting fluent answers. Language quality says nothing about the filter in the query. Read the query or run the golden questions.
  • Claude in Desktop. Claude does not run inside Tableau Desktop. Tableau Agent is the in-product assistant; Claude connects from outside through MCP or works on files and scripts.

On the brewhouse floor

A group running three breweries needs brewhouse yield to mean one thing before any agent touches it: extract in the wort over extract in the malt, measured at the same point in every brewhouse. Put that definition in one certified data source, give each site manager their own sign-in with row-level security on site. The agent in Slack can then answer "how did Brewery A's yield compare with last quarter" without inventing a formula. The golden questions are numbers the head brewer already knows by heart. My brewery production and yield dashboard shows how much of that definition work happens before the first chart.
