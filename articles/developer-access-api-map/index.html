Developer access and the Tableau API map

Join the Tableau Developer Program, request a free developer sandbox and learn which API does which job: REST, Tableau Server Client, Embedding, connected apps, Extensions, Hyper, Metadata, VizQL Data Service, webhooks, Pulse and MCP.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 0 Ankur Napa APIEmbeddingCloudMCP

Short answer

Tableau has about a dozen APIs and most people only ever need three of them. The REST API manages content and users on Tableau Cloud or Server. Tableau Server Client (TSC) is the Python library that wraps it. The Embedding API v3 puts a live viz inside your own web page. The rest are specialists: Extensions for code inside a dashboard, Hyper for building extract files, Metadata for lineage, VizQL Data Service for pulling numbers out of a published data source, webhooks for events, the Pulse API for metrics and the Tableau MCP server for AI clients.

To practise without touching production, join the Tableau Developer Program and request a free Tableau Cloud developer sandbox. It is a small personal site for testing APIs, not for real dashboards or real data.

The idea in one picture

Every API on this map talks to one of three things: the site, the viz or the file.

Two words you will meet everywhere. A personal access token (PAT) is a named secret a person creates in their account settings so a script can sign in as them. A connected app is a trust relationship a site admin sets up so your own application can sign users in with a short-lived JSON Web Token (JWT).

A ten-minute tour

You do not build anything here. You look at each piece so the later steps make sense.

  1. Find the programme. Go to the Tableau for Developers page. It points you to the DataDev community, the GitHub repositories and the sandbox. The page says "Join the DataDev program to get your free sandbox".
  2. Request the sandbox. Select Get a Sandbox. The form asks for your name, a business email, your organisation, company size, department, job role and country. The site is provisioned on Tableau Cloud and the activation instructions arrive by email. Tableau's confirmation page warns that the site can be updated at any time, that content can be wiped and that heavy workloads may be throttled. Treat it as scratch space and never load customer data into it.
  3. Open the REST API reference. On help.tableau.com, open API Versions. As of October 2026 the newest REST API version listed is 3.29, which matches Tableau Cloud and Server 2026.2. Every REST URL carries this number, so it is the first thing to check when a call fails.
  4. Look at TSC on GitHub. Open tableau/server-client-python. The package on PyPI is tableauserverclient, version 0.41 at the time of writing. It needs Python 3.10 or later.
  5. Open the Embedding API docs. Note the <tableau-viz> web component. One script tag and one HTML element put a viz on a page. That is v3; if a tutorial shows new tableau.Viz(...), it is the retired v2 library.
  6. Open the Extensions API site. At tableau.github.io/extensions-api note the .trex manifest file. The current library is 1.17.
  7. Open the Hyper API docs. At tableau.github.io/hyper-db note the package name: pip install tableauhyperapi.
  8. Open GraphiQL on your sandbox. Once the sandbox is live, sign in and go to https://<your-pod>.online.tableau.com/metadata/graphiql/. The Metadata API is always on in Tableau Cloud. On Tableau Server an admin must run tsm maintenance metadata-services enable first.
  9. Find where personal access tokens live. In your sandbox select your profile image > My Account Settings and scroll to Personal Access Tokens. If the section is missing, a site admin has to allow PAT creation first under Settings > Personal Access Tokens. Sites activated since 2023.2 start with it switched off. The next step on the roadmap creates the token.
  10. Look at the Tableau MCP repository. tableau/tableau-mcp is the official MCP server. It runs with npx @tableau/mcp-server and signs in with a PAT. The AI track covers it in depth.

What people get wrong

  • Using the sandbox as a free Tableau Cloud. It is for testing code against Tableau. The terms ask you not to store sensitive data. Content can disappear.
  • Treating a PAT like a password you share. A PAT acts as the person who created it, with all their permissions. One script, one token, one name. Tokens expire after 15 consecutive days without use. On Tableau Cloud the site admin sets the maximum lifetime, from 1 to 365 days. A PAT also cannot hold two Tableau Cloud sessions at once: sign in again with the same token and the first session ends.
  • Hardcoding the API version. A script pinned to an old version keeps working, but newer methods are missing. Read the version from GET /api/<version>/serverinfo or let TSC pick it with use_server_version=True.
  • Embedding with v2 code. The JavaScript API v2 (tableau-2.x.js) is the old library. New work uses Embedding API v3.
  • Reaching for REST when Metadata answers it. "Which workbooks use this column?" is one GraphQL query. Doing it with REST means downloading every workbook.
  • Using VizQL Data Service as a bulk export. It answers questions against a published data source. For moving whole tables, read from the source system or use Hyper.
  • Forgetting Pulse is Cloud only. Most Pulse API methods say "Not available for Tableau Server".

On the brewhouse floor

A brewery's data team uses the same map. TSC refreshes the packaging extract after the night shift closes the line. A Hyper script turns the fermentation sensor export into a .hyper file each morning. The Metadata API answers "what breaks if we rename the gravity column?" before anyone touches the brew log. The embed puts a hectolitres-packaged viz on the taproom manager's screen without giving them a Tableau login of their own.
