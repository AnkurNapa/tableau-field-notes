Table calcs: addressing, partitioning and Compute Using

Run the same running total, percent of total and rank three ways on one region by month table. Learn to read Compute Using so a table calculation means what you think.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa DesktopTable calcsCertification

Short answer

A table calculation runs on the numbers already in the view, after the query comes back. Every table calc splits the view's dimensions into two jobs. Partitioning fields define the groups the calculation restarts in. Addressing fields define the direction it moves within each group. Compute Using is how you assign those jobs. Table (across) and Table (down) assign them by the layout of the view. Specific Dimensions lets you tick the addressing fields yourself. Anything left unticked becomes a partition. The layout options break the moment someone swaps rows and columns. Specific Dimensions survives it.

What you will build

A region by month table of Harbour Goods sales for July to September 2026. On it you will run:

  • a running total that resets per region, then the same calc pointed the wrong way;
  • percent of total three ways, each answering a different question;
  • a rank of stores within their region.

Before you start

  • Tableau Desktop or Tableau Public, any recent version.
  • Download the cleaned Harbour Goods orders, products and stores. The cleaned file is the 60-row sample with its five deliberate faults removed: 55 orders.
  • Connect with Connect > To a File > Text file, choose the orders file and drag the other two onto the canvas. Tableau relates them on the shared id columns and shows store_id as Store Id.
  • Create Sales with Analysis > Create Calculated Field:
[Quantity] * [Unit Price] * (1 - [Discount])

Steps

1. Build the grid

  1. Drag Region to Rows. Tableau sorts it alphabetically: East, North, South, West.
  2. Drag Order Date to Columns. It lands as YEAR(Order Date). Right-click it and pick the first Month in the menu, the discrete date part. You get three columns: July, August and September.
  3. Drag Sales to Text on the Marks card.

Twelve numbers. Keep this sheet; duplicate it for each step with right-click on the sheet tab and Duplicate.

2. Running total the right way

  1. Right-click SUM(Sales) on the Marks card and select Quick Table Calculation > Running Total. A triangle appears on the pill.
  2. Right-click it again and select Edit Table Calculation.

The dialog shows Compute Using: Table (across). Across means the calc moves along the months. Region is not in the direction of travel, so Tableau treats it as the partition and the total restarts on every row. That is what you want: the West row climbs from July to September and stops at West's quarter total.

3. Point it the wrong way

In the same dialog choose Table (down). Now the calc runs down the regions within each month. The September column reads East, East plus North and so on, finishing at the September total for the whole company. Nobody asks for that number. It looks plausible, which is why it ships.

Switch to Specific Dimensions. Tick Month of Order Date and leave Region unticked. This is the same as Table (across), but it is written in terms of fields, not layout. Drag Region to Columns and Order Date to Rows to swap the axes. The Specific Dimensions version keeps meaning "running total over months per region". A Table (across) version would now run over regions.

When more than one field is ticked, At the level and Restarting every appear. Restarting every names a ticked field that should act as a partition, which is useful when a date hierarchy is split across Year and Month.

4. Percent of total, three questions

Duplicate the grid. Right-click SUM(Sales) and select Quick Table Calculation > Percent of Total. Then try each setting in Edit Table Calculation:

  • Table (across): each region's months add to 100%. Question: "How did each region's quarter split by month?"
  • Table (down): each month's regions add to 100%. Question: "Which region carried July?"
  • Table with both fields ticked under Specific Dimensions, or the layout option Table (across then down): all twelve cells add to 100%. Question: "What share of the quarter is this cell?"

Same pill, same triangle, three different answers. The only way a reader can tell is a title that says which one it is.

5. Rank stores within their region

  1. New sheet. Drag Region then Store Id to Rows and Sales to Text.
  2. Drag Sales to Text again, then right-click the new pill and select Quick Table Calculation > Rank.
  3. In Edit Table Calculation choose Specific Dimensions, tick Store Id only and leave Region unticked.

Region is now the partition, so every region has a number 1. Tick both fields and the rank runs across the whole company, one to six.

6. Percent difference from the previous month

On a fresh copy of the grid, select Quick Table Calculation > Percent Difference. It defaults to Table (across) and compares each month with the one before. July is blank because it has no previous month. That blank is correct, not missing data.

Where this breaks

  • The layout options move with the layout. Table (across) is tied to whatever is on Columns. Anyone who pivots the view changes the meaning silently. Use Specific Dimensions for anything that will be published.
  • Filters remove the rows the calc needs. A table calc sees only marks in the view. Filter out July and August's percent difference turns blank, because its previous month is gone. The fix is a table calculation filter, covered in the order of operations.
  • Missing marks. Chennai sold nothing in Home this quarter. A running total over categories steps straight past it. Use Analysis > Table Layout > Show Empty Rows or pad the data if a gap should show as zero.
  • Sort order. Running totals and ranks follow the sort. A region sorted by sales descending gives a different running total down than the alphabetical sort above.
  • Table calc or LOD? If the number must be stable whatever the view, or used in a filter before aggregation, it belongs in an LOD expression.

Next on the roadmap

Filters and table calcs meet in a strict sequence. The order of operations shows where each one runs and how to keep a percent of total intact under a filter.

On the brewhouse floor

A brewer tracks gravity readings per fermenter, one row per tank and one column per day. A running total of volume packaged should restart per tank, which is Specific Dimensions with Day ticked and Tank left as the partition. Percent difference from the previous reading shows how fast each ferment is slowing. Point it down instead of across and it compares tank 3 with tank 2 on the same day, a number that looks scientific and means nothing.
