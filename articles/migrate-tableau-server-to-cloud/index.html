Migrate Server to Cloud

Plan a Tableau Server to Tableau Cloud move as inventory, cleanup, identity, pilot and cutover. Use the Migration SDK for the move itself. The Content Migration Tool is for Server to Server and project to project work.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 4 Ankur Napa ServerCloudAPICertification

Short answer

Pick the right tool first, because the obvious one is wrong. The Content Migration Tool (CMT) copies content between Tableau Server sites, between installations or between projects on Tableau Cloud. Tableau's own help says it is not recommended for Tableau Server to Tableau Cloud. For that move, Tableau points to the Tableau Migration SDK, a Python or .NET framework you code against. It moves users, groups, group sets, projects, data sources, workbooks, custom views, extract refresh schedules, subscriptions, favourites, Prep flows and flow tasks through the REST API.

The tool is the small part. A migration is five phases: inventory, cleanup, identity and data access, pilot and cutover. Most of the risk sits in the first and the third.

What the SDK does not migrate, per its supported content page: data source revision history, managed OAuth embedded credentials (those data sources show as failed in the manifest), workbook data acceleration settings and labels. Flow favourites may also be skipped. Server-to-Server and Cloud-to-Cloud moves are not supported by the SDK. The CMT installs on Windows.

Reference design

Start the inventory from the repository, where Server keeps everything Cloud will never show you. This lists workbooks with their project, owner, size and last view:

SELECT w.project_name,
       w.name                         AS workbook,
       w.owner_name,
       ROUND(w.size / 1048576.0, 1)   AS size_mb,
       MAX(vs.last_view_time)         AS last_viewed
FROM _workbooks w
LEFT JOIN _views_stats vs ON vs.views_workbook_id = w.id
GROUP BY w.project_name, w.name, w.owner_name, w.size
ORDER BY last_viewed NULLS FIRST;

Anything not viewed in 90 days goes to the owner with a question: migrate, or archive? In most estates the honest answer for a large share is archive. That is the cheapest migration there is.

Questions to ask the client

  1. How many sites, projects, workbooks and data sources? How many were opened in the last 90 days?
  2. Which data sources are on-premises? Which use embedded passwords or OAuth?
  3. Which features in use are Server only: Kerberos delegation, custom TSM settings, repository reports, scripts calling TSM?
  4. Does any extract take more than two hours to refresh? Cloud cancels it.
  5. Are usernames on Server the same as the usernames the Cloud IdP will send? If not, who owns the mapping?
  6. Which links to Tableau live in other systems: portals, emails, wikis, embedded apps? They will all change.
  7. What is the freeze window? Who signs off the pilot?
  8. When does the Server licence or hardware lease end? That date is the real deadline.

Review checklist

  • Inventory complete, with last-view dates and owners for every workbook and data source.
  • Stale content archived and owners of departed staff reassigned before migration, not after.
  • Cloud site has SSO and SCIM working, groups created and projects locked before any content arrives.
  • A username mapping exists and is tested for every user who owns content.
  • Bridge pools refresh every on-premises source in the pilot.
  • Embedded credentials re-entered for sources the SDK cannot carry, including managed OAuth.
  • Pilot users compared numbers on Server and Cloud for their key views and signed off.
  • Every repository report has a replacement in Admin Insights or the Activity Log.
  • Old Server links redirect or show a notice. Server is read only for a fixed period, then switched off.

Anti-patterns

  • Lift and shift. Migrating everything, including the 400 workbooks nobody has opened since 2023, so the Cloud site starts as messy as the Server.
  • CMT for Server to Cloud. It is the tool people know. Tableau's help says not to use it for this path.
  • Identity last. Content arrives before users exist, so ownership falls to the migration account and nobody can find their work.
  • No freeze. Authors keep publishing to Server during the final run. Their changes vanish at cutover.
  • Forgetting the links. The dashboards move. The bookmark in the sales team's browser does not.

On the brewhouse floor

A winery moving its reporting to Tableau Cloud should run the move like a racking: only the clear wine goes into the new barrel. The harvest intake, the cellar operations and the sales dashboards that people open every week migrate. The fourteen copies of the 2022 vintage blending analysis stay behind as lees. Do the pilot with the cellar team after harvest, never during it, because nobody signs off a test while the presses are running.
