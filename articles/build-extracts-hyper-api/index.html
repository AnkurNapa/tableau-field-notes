Build and update extracts with the Hyper API

Create a .hyper extract from a CSV in Python with tableauhyperapi, update it with corrections and new orders without rebuilding, fail safely on bad data and publish it to Tableau Cloud with Tableau Server Client.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 3 Ankur Napa APIPrepCloudPerformance

Short answer

The Hyper API is Tableau's extract engine as a library. pip install tableauhyperapi gives you HyperProcess, Connection and SQL. You define the table, COPY a CSV into it and you have a .hyper file Tableau opens like any extract. To update it, open the same file with CreateMode.NONE, stage the new rows in a temporary table, delete the keys that arrive again and insert. Build into a temporary file and swap it in only when the load succeeds. Then publish it with Tableau Server Client in Overwrite mode, because a published .hyper has no live source for Tableau Cloud to refresh.

The symptom

Harbour Goods gets a nightly orders export as a CSV from its till system. The workbook was built on the CSV and published as an extract. Two things go wrong:

  • Tableau Cloud cannot refresh it. The file sits on someone's laptop, so every morning a person republishes by hand.
  • Late corrections arrive. An order placed on 29 September has its quantity fixed on 2 October. Appending the new file double counts that order.

Measure it

Start with the facts the fix has to preserve. These come from the sample files, computed in Python and confirmed in Hyper:

Net sales is quantity * unit_price * (1 - discount). The update file holds 38 new October orders (HG-40101 to HG-40138) and corrected copies of two September orders, HG-40054 and HG-40055, each with one more unit. A naive append gives 95 rows. The right answer is 93.

Time and size matter too. On my laptop the build below took 0.12 to 0.47 seconds and wrote a 64 KB file; most of that is starting the Hyper process. Measure your own on real volumes before promising a refresh window.

Fix it

1. Install

python3 -m venv .venv && source .venv/bin/activate
pip install tableauhyperapi tableauserverclient

The package ships its own hyperd engine for Windows, macOS and Linux. Nothing else to install.

2. Build the extract

build_orders_hyper.py:

import sys
from pathlib import Path

from tableauhyperapi import (
    Connection, CreateMode, HyperProcess, NOT_NULLABLE, NULLABLE, SqlType,
    TableDefinition, TableName, Telemetry, escape_string_literal,
)

CSV = Path(sys.argv[1] if len(sys.argv) > 1 else "harbour-goods-orders-clean.csv")
HYPER = Path("harbour-goods-orders.hyper")
BUILD = HYPER.with_name("harbour-goods-orders.building.hyper")

ORDERS = TableDefinition(
    table_name=TableName("Extract", "Extract"),
    columns=[
        TableDefinition.Column("order_id", SqlType.text(), NOT_NULLABLE),
        TableDefinition.Column("order_date", SqlType.date(), NOT_NULLABLE),
        TableDefinition.Column("store_id", SqlType.text(), NOT_NULLABLE),
        TableDefinition.Column("product_id", SqlType.text(), NOT_NULLABLE),
        TableDefinition.Column("quantity", SqlType.int(), NOT_NULLABLE),
        TableDefinition.Column("unit_price", SqlType.numeric(10, 2), NOT_NULLABLE),
        TableDefinition.Column("discount", SqlType.numeric(4, 2), NULLABLE),
    ],
)

with HyperProcess(telemetry=Telemetry.DO_NOT_SEND_USAGE_DATA_TO_TABLEAU) as hyper:
    with Connection(
        endpoint=hyper.endpoint,
        database=BUILD,
        create_mode=CreateMode.CREATE_AND_REPLACE,
    ) as conn:
        conn.catalog.create_schema(ORDERS.table_name.schema_name)
        conn.catalog.create_table(ORDERS)
        loaded = conn.execute_command(
            f"COPY {ORDERS.table_name} FROM {escape_string_literal(str(CSV))} "
            "WITH (format => 'csv', header => true)"
        )
        units, net = conn.execute_list_query(
            f"SELECT SUM(quantity), SUM(quantity * unit_price * (1 - discount)) "
            f"FROM {ORDERS.table_name}"
        )[0]
        print(f"loaded {loaded} rows, {units} units, net {net}")

# Swap in the new file only after the load succeeded.
BUILD.replace(HYPER)

Why each piece is there:

  • Explicit types. numeric(10, 2) for money, date for dates. Let Hyper guess and you get text. Every sum then becomes a string fight in Tableau.
  • NOT_NULLABLE on the key and the quantity. Bad rows fail the load instead of slipping through as nulls.
  • "Extract"."Extract". The schema and table name Tableau uses in its own single-table extracts. Other names can work, but this one is the safe default.
  • COPY. The fastest way in. It reads the file inside the Hyper process, not row by row through Python.
  • The swap. CREATE_AND_REPLACE wipes the target file first. Building into a second file means yesterday's extract survives a bad night.

Run it:

python build_orders_hyper.py

3. Apply corrections and new rows

update_orders_hyper.py:

from pathlib import Path

from tableauhyperapi import (
    Connection, CreateMode, HyperProcess, TableName, Telemetry,
    escape_string_literal,
)

UPDATE_CSV = Path("build-extracts-hyper-api.csv")
HYPER = Path("harbour-goods-orders.hyper")
ORDERS = TableName("Extract", "Extract")

with HyperProcess(telemetry=Telemetry.DO_NOT_SEND_USAGE_DATA_TO_TABLEAU) as hyper:
    with Connection(hyper.endpoint, HYPER, CreateMode.NONE) as conn:
        # Stage the new file in a temporary table with the same columns.
        conn.execute_command(
            f"CREATE TEMPORARY TABLE staging AS SELECT * FROM {ORDERS} LIMIT 0"
        )
        conn.execute_command(
            f"COPY staging FROM {escape_string_literal(str(UPDATE_CSV))} "
            "WITH (format => 'csv', header => true)"
        )
        # Replace any order that arrives again, then add the rest.
        replaced = conn.execute_command(
            f"DELETE FROM {ORDERS} WHERE order_id IN (SELECT order_id FROM staging)"
        )
        added = conn.execute_command(f"INSERT INTO {ORDERS} SELECT * FROM staging")
        rows, units, net = conn.execute_list_query(
            f"SELECT COUNT(*), SUM(quantity), "
            f"SUM(quantity * unit_price * (1 - discount)) FROM {ORDERS}"
        )[0]
        print(f"replaced {replaced}, inserted {added}")
        print(f"now {rows} rows, {units} units, net {net}")

Delete then insert by order_id is an upsert. Run it twice and the second run replaces the same 40 rows and leaves the totals alone. That is the property you want from anything scheduled.

4. Publish it

publish_hyper.py, using the Harbour Sales project from Automate with Tableau Server Client:

import os

import tableauserverclient as TSC

HYPER_FILE = "harbour-goods-orders.hyper"
DATASOURCE_NAME = "Harbour Goods Orders Extract"
PROJECT = "Harbour Sales"

auth = TSC.PersonalAccessTokenAuth(
    os.environ["TABLEAU_PAT_NAME"],
    os.environ["TABLEAU_PAT_SECRET"],
    site_id=os.environ["TABLEAU_SITE"],
)
server = TSC.Server(os.environ["TABLEAU_SERVER"], use_server_version=True)

with server.auth.sign_in(auth):
    projects = [p for p in server.projects.filter(name=PROJECT) if p.parent_id is None]
    if not projects:
        raise SystemExit(f"Project {PROJECT} not found")
    ds = server.datasources.publish(
        TSC.DatasourceItem(projects[0].id, name=DATASOURCE_NAME),
        HYPER_FILE,
        mode=TSC.Server.PublishMode.Overwrite,
    )
    print(f"Published {ds.name} ({ds.id})")

The nightly job becomes three commands: build or update, check the totals, publish.

Where this breaks

  • Dirty source files. The raw harbour-goods-orders.csv has a blank quantity on one row and a date of 2026-09-31 on another. With quantity set NOT_NULLABLE Hyper stops at the blank: The scanned data violates the NOT NULL constraint of column "quantity". Make the column nullable and it stops at the impossible date instead. Good. Clean upstream or in Prep; do not loosen the types to make the error go away.
  • The update is not atomic. If the process dies between DELETE and INSERT, the file is missing those orders. For anything that matters, copy the file, update the copy and swap it in, the same way the build does.
  • Refresh does nothing. A published .hyper has no connection to refresh from. Republish it instead of scheduling a refresh.
  • Keys you do not have. The upsert depends on order_id being unique and stable. If the source reissues IDs, you need a composite key or a full rebuild.
  • Size limits. Large files publish in chunks through TSC, but Tableau Cloud still applies site storage and extract size limits. Check them before you design a 50 GB nightly push.
  • Package versions. tableauhyperapi versions look like 0.0.26479. Pin the one you tested in requirements.txt; a new build can change the engine underneath you.

On the brewhouse floor

A brewery's packaging line writes a CSV every shift: batch, line, cases packed, cases rejected. Corrections arrive when QA re-grades a pallet two days later. The same delete-then-insert by batch and shift keeps the extract honest, so the reject rate on the dashboard matches the QA log instead of counting a re-graded pallet twice. My packaging-line OEE dashboard runs on exactly that kind of feed.
