TabPy analytics extensions: count the calls, then question the need

A TabPy outlier score returns nulls and calls Python once per store. Measure the calls in the TabPy log, fix the addressing, prove it, then rebuild the same score with native table calculations and decide whether you needed Python at all.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 3 Ankur Napa AIDesktopServerCloudPerformanceSecurityTable calcs

Short answer

The SCRIPT functions (SCRIPT_REAL, SCRIPT_INT, SCRIPT_STR and SCRIPT_BOOL) are table calculations. Tableau aggregates the data to the view's level of detail, splits it into partitions using Compute Using and sends each partition to TabPy as a separate call. Get the addressing wrong and you pay for many calls. Any statistic that needs the whole set comes back wrong or null. Put the dimensions you want Python to see on addressing, count the calls in the TabPy log. Before you keep the calculation, check whether WINDOW functions already do the job. TabPy earns its place for a trained model or a library Tableau lacks, not for arithmetic.

The symptom

A store manager's dashboard at Harbour Goods has a bar per store for July to September 2026 and an outlier score beside it, a z-score of each store's net sales against the six stores. The calculation:

// Store Z-Score (TabPy)
SCRIPT_REAL("
import statistics as st
m = st.mean(_arg1)
sd = st.pstdev(_arg1)
return [(x - m) / sd for x in _arg1]
", SUM([Net Sales]))

Store Id is on Columns, SUM(Net Sales) on Rows and the score on Label. Every score is blank, the view takes noticeably longer than the same view without the score. The TabPy console shows errors. Remove Store Id from the view and the error goes away, which is the clue.

The data is the Harbour Goods orders used across the AI track: first-pulse-metric-net-sales.csv, filtered to July to September 2026.

Measure it

Count the calls. Start TabPy with call logging on. In the TabPy config file set:

[TabPy]
TABPY_PORT = 9004
TABPY_LOG_DETAILS = true

Then start it with tabpy --config=<path-to-config-file>. Each request from Tableau to /evaluate now writes a log line with the caller and URL. Refresh the view once in Tableau Desktop and count the /evaluate lines. With the broken view there are six, one per store.

Read Compute Using. On the score pill select Edit Table Calculation. Compute Using is set to Table (down), left over from when the stores sat on Rows and someone swapped the axes. Store Id now runs across the Columns shelf, so down means each store is its own partition. Each call to Python receives a list with one value. The population standard deviation of one value is 0, the division fails and Tableau gets nothing back.

Time it. Select Help > Settings and Performance > Start Performance Recording, refresh the view, then Stop Performance Recording. The recording workbook opens. Compare the time for this sheet with and without the score on Label. The analytics extension round trips sit inside the table calculation and query events; the exact event labels vary by version, so compare totals for the sheet rather than hunting for one event name.

Check the connection. In Desktop the connection lives under Help > Settings and Performance > Manage Analytics Extension Connection. Confirm the server name, port 9004 and whether Require SSL is ticked. A wrong host shows as an error on every mark, not as nulls, so it is a different problem.

Fix it

  1. On the score pill select Edit Table Calculation.
  2. Set Compute Using to Store Id, or to Table (across). Store Id is now addressing, not partitioning.
  3. Refresh. TabPy receives one list of six values and returns six scores.

Expected scores for July to September 2026, mean 25,510.97 and population standard deviation 9,666.13:

Now ask the harder question: did this need Python? The same score in native Tableau:

// Store Z-Score (native)
(SUM([Net Sales]) - WINDOW_AVG(SUM([Net Sales])))
  / WINDOW_STDEVP(SUM([Net Sales]))

With the same Compute Using it returns the same six numbers, with no server to run, patch or secure. Keep TabPy for what Tableau cannot do: a model you trained and deployed to TabPy with tabpy.deploy, called from a calculation with tabpy.query, or a library such as a forecasting package that has no Tableau equivalent. The MODEL_EXTENSION functions also work only with TabPy models.

Harden the server before it leaves your laptop.

  • Turn off ad hoc code. Set TABPY_EVALUATE_ENABLE = false in production and call only deployed functions. With evaluate on, any workbook author can send Python that reads files, installs packages and opens network connections on the TabPy host.
  • Require sign-in. Set TABPY_PWD_FILE and tick Sign in with a username and password on the connection.
  • Use TLS. Set TABPY_TRANSFER_PROTOCOL = https with a certificate and key. Tableau Cloud refuses self-signed certificates; it needs one from a trusted certificate authority.
  • Allow Tableau Cloud in. Tableau Cloud reaches your TabPy server from 44.224.205.196 and 44.230.200.109. Allow those and nothing else on the TabPy port.
  • Configure it on the site. On Tableau Cloud a site administrator selects Settings > Extensions > Analytics Extensions > Enable analytics extensions for site > Create new connection and picks TabPy. On Tableau Server 2020.2 and later the connection is also per site.

The call counts follow from the partitioning and you can reproduce them from the log. The timings are illustrative, not measured; they depend on where TabPy runs and the network between it and Tableau. Measure your own with the Performance Recorder before and after.

Where this breaks

  • Row counts must match. Tableau expects one value back or the same number of values it sent. A Python function that drops nulls returns a shorter list and the whole calculation fails.
  • Level of detail. TabPy sees aggregated values at the view's level. Add Order Id to Detail and it sees 55 orders instead of six stores. The z-score then means something else.
  • Filters change the answer. As a table calculation the score is computed after filters. Filter out Kolkata and every other store's score changes. That is usually what people want; say so on the dashboard.
  • Timeouts. Ad hoc scripts stop at TABPY_EVALUATE_TIMEOUT, 30 seconds by default. Requests over TABPY_MAX_REQUEST_SIZE_MB, 100 MB by default, are rejected.
  • Extracts and published workbooks. The calculation runs where the viz renders. A workbook published to Tableau Cloud calls the site's analytics extension connection, not the one on your laptop.

On the brewhouse floor

A brewery that sends fermentation readings to TabPy to forecast when each tank reaches terminal gravity has the same trap. If Tank Id ends up as a partition, each call gets one tank's curve, which is right for a per-tank forecast and wrong for any comparison across tanks. Decide which one you want, then count the calls in the log. A simple flag such as "gravity more than two standard deviations from the cellar average" needs no Python at all. My live fermentation monitoring dashboard uses a TabPy forecast where a model genuinely earns its place.
