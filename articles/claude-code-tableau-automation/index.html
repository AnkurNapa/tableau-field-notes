Claude Code for Tableau automation: scripts, XML and reviews

Have Claude Code write a Tableau Server Client script with a dry run, change a calculation in workbook XML with a backup and a verification step. Then review a dashboard against a checklist. Each task ends with the check that caught Claude's mistake.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 2 Ankur Napa ClaudeAIAPIServerCloudDesign

Short answer

Claude Code is Claude in your terminal, working on files in a folder you choose. For Tableau that means three useful jobs: writing Python against the REST API with Tableau Server Client (TSC), editing .twb workbook XML that Desktop would make you click through by hand. The third is reading a workbook to review it against your team's checklist. It does not drive Tableau Desktop and it does not run inside it. The rules that make it safe are the same rules you would give a new analyst: credentials from the environment, a dry run before anything changes, a backup before any file edit and a check you can read in ten seconds.

What you will build

A folder called harbour-tableau-ops with three things in it:

  1. inventory_and_refresh.py: lists the workbooks in the Harbour Goods project to a CSV and refreshes the Harbour Goods Orders extract, dry run by default.
  2. edit_calc.py and compare_twb.py: change the formula of one calculated field in a .twb after taking a timestamped backup, then list every attribute that changed.
  3. REVIEW.md: a dashboard checklist Claude Code applies to a workbook file.

The data source is the one from Your first Pulse metric, built from first-pulse-metric-net-sales.csv. Any workbook of your own works for parts 2 and 3; use a copy.

Before you start

  • Claude Code installed and signed in. Start it in the new folder with claude.
  • Python 3.10 or later and TSC: pip install tableauserverclient. The current release on GitHub is v0.41 from June 2026.
  • A personal access token for a test site or a developer sandbox, not production. Export it in your shell, never in a file Claude Code might commit:
export TABLEAU_SERVER="https://<your-pod-or-server>"
export TABLEAU_SITE="<site-content-url>"
export TABLEAU_PAT_NAME="<pat-name>"
export TABLEAU_PAT_VALUE="<pat-secret>"
  • A CLAUDE.md in the folder with the house rules. Claude Code reads it at the start of every session:
# Rules for this folder
- Read Tableau credentials from TABLEAU_* environment variables only.
- Every script that changes Tableau has a dry run as the default and an --apply flag.
- Before editing any .twb or .twbx, copy it to <name>.<timestamp>.bak.
- Never edit a .twbx in place. Unzip to a working folder, edit the .twb, zip again.
- Use only the Python standard library plus tableauserverclient.

Steps

1. A TSC script with a dry run

Write inventory_and_refresh.py. Sign in with a PAT from the TABLEAU_*
environment variables. List every workbook in the project "Harbour Goods"
with name, owner id and updated date to workbooks.csv. Then refresh the
published data source "Harbour Goods Orders" and wait for the job.
Dry run by default; refresh only with --apply.

Claude Code writes the file and shows it to you before saving. The version worth keeping looks like this:

"""List workbooks in one project and refresh one data source. Dry run unless --apply."""
import csv
import os
import sys

import tableauserverclient as TSC

PROJECT = "Harbour Goods"
DATASOURCE = "Harbour Goods Orders"


def main(apply: bool) -> None:
    auth = TSC.PersonalAccessTokenAuth(
        os.environ["TABLEAU_PAT_NAME"],
        os.environ["TABLEAU_PAT_VALUE"],
        site_id=os.environ["TABLEAU_SITE"],
    )
    server = TSC.Server(os.environ["TABLEAU_SERVER"], use_server_version=True)
    with server.auth.sign_in(auth):
        rows = [
            (wb.name, wb.owner_id, wb.updated_at.isoformat() if wb.updated_at else "")
            for wb in TSC.Pager(server.workbooks)
            if wb.project_name == PROJECT
        ]
        with open("workbooks.csv", "w", newline="") as f:
            csv.writer(f).writerows([("name", "owner_id", "updated_at"), *rows])
        print(f"{len(rows)} workbooks in {PROJECT} written to workbooks.csv")

        matches = list(server.datasources.filter(name=DATASOURCE))
        if len(matches) != 1:
            sys.exit(f"Expected one data source called {DATASOURCE}, found {len(matches)}")
        if not apply:
            print(f"Dry run: would refresh {DATASOURCE} ({matches[0].id})")
            return
        job = server.datasources.refresh(matches[0])
        job = server.jobs.wait_for_job(job, timeout=600)
        print(f"Refresh finished: {job.finish_code}")


if __name__ == "__main__":
    main(apply="--apply" in sys.argv)

The check that catches the mistake. A typical first draft looks the data source up with server.datasources.get() and takes the first item whose name matches. It runs cleanly on a sandbox. Then a colleague publishes a second Harbour Goods Orders into another project. The dry run prints a different LUID from the one in the browser address bar. Names are not unique across projects; LUIDs are. The len(matches) != 1 guard is the fix. The habit is to compare the dry run's LUID with the one you expect before you add --apply. TSC.Pager matters too: a plain get() returns only the first page of 100 items, so a site with 140 workbooks silently loses 40.

Run it with python3 inventory_and_refresh.py, read the output, then python3 inventory_and_refresh.py --apply.

2. Edit workbook XML with a backup

A .twb is XML. A .twbx is a zip holding a .twb plus extracts and images. Changing one calculation across ten workbooks is faster in XML than in Desktop. It is also riskier.

Write edit_calc.py: arguments are a .twb path, a calculated field caption and
a new formula. Copy the file to a timestamped .bak first. Change the formula
on every column element with that caption that has a calculation child.
Exit without writing if nothing matches. Standard library only.

The version that passed the checks:

"""Change one calculated field's formula in a .twb, after taking a backup."""
import shutil
import sys
import xml.etree.ElementTree as ET
from datetime import datetime

ET.register_namespace("user", "http://www.tableausoftware.com/xml/user")


def main(path: str, caption: str, formula: str) -> None:
    backup = f"{path}.{datetime.now():%Y%m%d-%H%M%S}.bak"
    shutil.copy2(path, backup)
    tree = ET.parse(path)
    hits = 0
    for col in tree.iter("column"):
        calc = col.find("calculation")
        if col.get("caption") == caption and calc is not None:
            calc.set("formula", formula)
            hits += 1
    if hits == 0:
        sys.exit(f"No calculated field captioned {caption!r}; nothing written. Backup: {backup}")
    tree.write(path, encoding="utf-8", xml_declaration=True)
    print(f"Updated {hits} column element(s). Backup: {backup}")


if __name__ == "__main__":
    main(*sys.argv[1:4])

Run it on a copy:

python3 edit_calc.py "Harbour Sales copy.twb" "Net Sales" "[Quantity] * [Unit Price] * (1 - [Discount])"

Then ask Claude Code for compare_twb.py, a comparison script that parses the backup and the new file and prints every attribute that changed:

"""Print every element whose tag, attributes or text differ between two .twb files."""
import sys
import xml.etree.ElementTree as ET


def main(old: str, new: str) -> None:
    a, b = list(ET.parse(old).iter()), list(ET.parse(new).iter())
    if len(a) != len(b):
        sys.exit(f"Element count changed: {len(a)} -> {len(b)}")
    changes = 0
    for x, y in zip(a, b):
        if (x.tag, x.attrib, (x.text or "").strip()) != (y.tag, y.attrib, (y.text or "").strip()):
            changes += 1
            for k in sorted(set(x.attrib) | set(y.attrib)):
                if x.get(k) != y.get(k):
                    print(f"<{y.tag}> {k}: {x.get(k)!r} -> {y.get(k)!r}")
    print(f"{changes} element(s) changed")


if __name__ == "__main__":
    main(sys.argv[1], sys.argv[2])

Run it:

python3 compare_twb.py "Harbour Sales copy.twb.<timestamp>.bak" "Harbour Sales copy.twb"

It should print only formula changes, one for the data source and one for each worksheet that uses the field, because Tableau repeats a calculation's definition in every worksheet's dependencies.

The check that catches the mistake. A typical first draft of edit_calc.py has no register_namespace line. The comparison script still reports only formula changes, because it compares parsed XML. A plain search does not agree:

grep -c "ns0:" "Harbour Sales copy.twb"

It returns a non-zero count. Python's XML library has renamed Tableau's user: namespace prefix to ns0: on every attribute that used it. The file is still valid XML, but you should not hand Tableau a file it never wrote in that shape. The fix is the one line at the top. Run the grep after every XML edit, open the file in Tableau Desktop and confirm the field shows the new formula before you copy the approach to the other nine workbooks. The quote style changes from single to double quotes on save; that is expected and harmless.

3. Review a dashboard against a checklist

Save the checklist as REVIEW.md in the folder:

# Dashboard review checklist
1. Every dashboard has a fixed size, not Automatic.
2. Every worksheet on a dashboard has a title a reader understands.
3. No more than four filter controls per dashboard.
4. Every filter control has "All" as a sensible default or a stated default.
5. Colours come from the team palette; list any hex code that is not in it.
6. No more than two font families.
7. Every calculated field has a comment explaining it.
8. No calculated field duplicates another under a different name.
Read "Harbour Sales copy.twb" and check it against REVIEW.md. For each item
give pass, fail or cannot tell from the XML. Quote the XML element that
supports each answer. Do not edit any file.

The check that catches the mistake. A first pass can mark item 1 a pass because it found <size maxheight='800' maxwidth='1200' ...>. Asked to quote the element in full, Claude shows minheight and minwidth with different values: a range, not a fixed size. Requiring the quoted evidence turns a confident pass into a correct fail. Items 2 and 4 are judgement calls; Claude's "cannot tell" is the honest answer. Those go to a person with the dashboard open.

Check it worked

  • The dry run prints one LUID and it matches the data source's address in the browser.
  • workbooks.csv has as many rows as the project page in Tableau shows workbooks, plus the header.
  • compare_twb.py lists only formula changes and grep -c "ns0:" returns 0.
  • Tableau Desktop opens the edited workbook and the calculation editor shows the new formula. With the shared orders file, SUM(Net Sales) moves from 163,146.00 before the edit to 156,269.85 after it, the discount coming off.
  • The review output quotes an XML element for every pass and fail.

Where this breaks

  • PAT sessions are single use at a time. A script and an MCP client on the same token sign each other out. Give automation its own token.
  • Site content URL, not display name. TABLEAU_SITE is the part after /site/ in the browser address bar. Empty means the default site on Tableau Server.
  • Editing a .twbx in place. Unzip, edit the .twb, zip again with the same internal paths, or let Desktop resave it.
  • Workbook XML is not a public API. Tableau can change its shape between versions. Keep XML edits small and repeatable and test each new Desktop version on a copy.
  • Untrusted files. The standard library parser is fine for workbooks your team saved. For files from outside, parse with defusedxml instead.
  • Claude Code runs commands. Keep permission prompts on for anything that touches Tableau. Keep production credentials out of the shell it uses.

On the brewhouse floor

A brewery that changed how it counts packaging loss has the same calculation in a dozen workbooks: yield, cost per hectolitre, the weekly brewhouse report. Claude Code can change the formula in all of them in a minute. The backup and the comparison script are what let the brewer sign it off. The check is a number the brewer already knows, last month's loss, coming out the same in every workbook after the edit. My COGS per hectolitre dashboard is the kind of workbook that carries such a shared formula.
