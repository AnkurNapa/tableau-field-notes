Why Tableau Prep exists and when you do not need it

Prep is a visual tool for cleaning and reshaping data before it reaches a workbook. Here is when to clean in Prep, in Desktop or upstream and how to read the flow and profile panes.

12 Oct 2026 Tableau as of October 2026 Checked against Tableau Help Level 0 Ankur Napa Prep

Short answer

Tableau Prep Builder is where you fix data before anyone builds a chart on it. You drag steps into a flow and every step shows you a profile of what the data looks like at that point. Desktop can do a lot of cleaning too, but it does it again every time someone opens the workbook. The next analyst repeats it in their own workbook. Prep does it once, writes the result to an extract, a published data source or a database table. It also leaves a visible record of what changed. If the same mess should be fixed for everyone, fix it upstream in the source system or the warehouse. Prep sits in the middle: the right place when you own the analysis but not the source.

Prep Builder comes with the Creator licence and runs on Windows and Mac. Creators can also build flows in the browser on Tableau Cloud and Tableau Server 2020.4 or later.

The idea in one picture

Where should a given fix live? A rough rule I use:

The problemFix it inWhy
A store ID typed in lower case by one tillPrep, then tell the till ownerYou need it fixed today; the root cause is theirs
A column that is wide (one column per month)PrepPivoting in Desktop is limited and repeated per workbook
A one-off grouping for one chartDesktopNobody else needs it
A ratio that must be computed after filtersDesktopPrep calculates row by row before anyone filters
A product hierarchy every team usesUpstream, in the warehouse or sourceOne definition, every tool
A broken export that drops rowsUpstreamPrep cannot clean rows that never arrived

The rule underneath: clean as far upstream as you have authority and no further downstream than the people who need the fix.

A ten-minute tour

You need Prep Builder (a trial is fine) and the shared sample harbour-goods-orders.csv. It holds 60 orders for Harbour Goods, a fictional retailer, from July to September 2026. Four of them are wrong on purpose.

  1. Open Prep Builder. The start page lists recent flows and some sample flows. Select Connect to Data > Text file and choose the orders CSV.
  2. Read the Input pane. An Input step appears in the Flow pane at the top. Below it the Input pane lists every field with a type icon and sample values. Note what Prep guessed for order_date and quantity. These are guesses from a sample, not facts.
  3. Add a Clean step. Select the plus icon on the Input step and choose Clean Step. The screen splits into the Profile pane (one card per field) and the data grid (the rows underneath).
  4. Read the store_id card. It shows seven bars. Six are the stores in the registry: ST-003, ST-007, ST-011, ST-014, ST-019 and ST-022. The seventh, ST-099, is one order for a store that does not exist. Select that bar; the data grid filters to that row and the other cards highlight where it sits.
  5. Read the quantity card. Look for a null and a negative value. Order HG-40056 has no quantity. Order HG-40057 has minus two, which is either a return or a typing error. Prep shows both; it cannot tell you which it is.
  6. Read the order_date card. Order HG-40059 carries 2026-09-31. September has 30 days. Depending on how Prep typed the field, it shows as null or as an odd text value.
  7. Read the order_id card. There are 60 rows but 59 distinct IDs. HG-40017 appears twice with identical values: an export that sent one row twice.
  8. Make one change and watch it record. On the store_id card, right-click ST-099 and choose Exclude. Open the Changes pane on the left edge of the Profile pane. Your change is listed there with an icon. You can edit, reorder or delete it. That list is the record a workbook calculation never gives you.
  9. Undo it. Delete the change from the Changes pane. Whether to exclude a real order from an unknown store is a business decision, not a cleaning one. The Level 1 walkthrough keeps rows like it and labels them instead.

That is the whole mental model. Input, steps, profile, changes, output. The rest of the Prep track adds step types, not new ideas.

What people get wrong

  • Treating Prep as a reporting tool. Prep calculates row by row and in fixed groups before the data reaches a view. It has no idea what filter a reader will pick on a dashboard. Ratios that must respect filters belong in Desktop.
  • Cleaning in Prep what should be fixed at the source. If the till system has sent lower-case store IDs for two years, a Prep step hides the problem for ever. Fix it in the flow, then raise it with whoever owns the till.
  • Trusting the profile as the full data. The profile is drawn from a sample of rows by default. On a small file that is all of it; on a large table it is not. A value missing from the profile can still be in the data.
  • Expecting Prep to run on a schedule by itself. Prep Builder runs flows when you press Run, or from the command line. Scheduling on Tableau Cloud or Server needs Prep Conductor, which is part of Data Management. Creating and running flows by hand on the web does not.
  • Using Prep for one chart. A flow is a maintained asset. If one analyst needs one grouping for one chart, a Desktop group is cheaper.

On the brewhouse floor

Every brewery keeps a log of what went into each batch and where it ended up. In a small brewery it is a spreadsheet, filled in by whoever was on shift, with the fermenter written three different ways and the occasional batch volume typed in the wrong unit. That sheet is the source and the brewer who owns it is the person to fix it upstream. Prep is the right place for the fixes you need today, such as matching fermenter names and flagging a volume that cannot be right, so the brewery production and yield dashboard reads one clean table instead of the raw sheet.
